# T03 执行清单

## 启动条件

- [ ] 核对 [PRD](prd.md)、[设计](design.md)、权威文档及本次工作区变更。
- [ ] 核对最终集成验收依赖（不等同于全部启动条件，分阶段输入见下文及父任务总表）：[T01 建立开发与回归基线](../10-10-v1-baseline-runtime/prd.md)
- [ ] 将技术未知项落实为可验证方案；涉及新产品取舍先按 DECISIONS 流程确认。
- [ ] 细化设计后完成执行前评审；按 Trellis 流程启动本子任务，不以父任务代替实现任务。

## 分阶段交付

A：T01 本机基线明确后冻结最小用户输入、可信预设、度量/布局/错误契约，供上下游并行；B：实现契约校验与合成回归，可独立验收；下游 T04～T09 再补真实资源集成证据，不反向阻塞 T03 完成，也不在渲染端补默认排版。

阶段输入与整项验收依赖以 [父任务总表](../10-10-learn-v1/task-map.md) 为准；只完成阶段不能将整项标记完成。

## 交付步骤

- [ ] 对照现有 SquareTextDocument/DocumentLayout 梳理最小演进方案。
- [ ] 明确预设提供的默认文字规则与可扩展布局结果。
- [ ] 迁移现有调用并验证旧基准；记录单位、精度与序列化边界。

## 验收映射

- [ ] T03-AC1：标题、正文、段落、对齐、首行缩进及样式绑定具有类型契约和边界校验。
- [ ] T03-AC2：方格与拼音行带使用各自承载模型，共用通用文本能力；仅开放 D-040 确认的文字设置，不新增用户尺寸、字体、字号或灰度选择器。
- [ ] T03-AC3：保留显式空行与输入顺序，维持空白/填字自动推导和描红同布局规则。

- [ ] T03-AC4：明确 D-040 对齐/缩进的允许输入、缺省/重置来源；用户输入与可信几何/文字/线型预设分离。布局输出包含供两渲染器一致使用的字体/样式引用、定位约定及结构化错误；渲染器不另定默认值或分页。

## 验证与收尾

- [ ] 在 `packages/paper-core` 执行 `npm test`（包含 TypeScript 编译）；缺依赖先 `npm install`。涉及布局时更新基准，并将渲染/实印剩余项交 T10。
- [ ] 检查文档差异、相对引用及与 DECISIONS/PAPER_PRESETS 的一致性。
- [ ] 将本轮实际验证、失败原因与剩余项目记录到任务证据；必要时更新 TESTING/ROADMAP。
- [ ] 检查无正文、敏感凭据或未授权字体分发进入日志/提交。
- [ ] 独立检查通过后再标记完成，恢复/回退不得覆盖他人变更。
