# T09 执行清单

## 启动条件

- [ ] 核对 [PRD](prd.md)、[设计](design.md)、权威文档及本次工作区变更。
- [ ] 核对最终集成验收依赖（不等同于全部启动条件，分阶段输入见下文及父任务总表）：[T07 实现排版版本与摘要协议](../10-10-v1-layout-versions/prd.md)
- [ ] 将技术未知项落实为可验证方案；涉及新产品取舍先按 DECISIONS 流程确认。
- [ ] 细化设计后完成执行前评审；按 Trellis 流程启动本子任务，不以父任务代替实现任务。

## 分阶段交付

A：现有四模板几何生成真实 A4 矢量空白 PDF 并验尺寸/完整墨迹；B：接真实方格字体、多页；C：接拼音/描红/T07.B 并验证嵌入、字形与云端限制。不得以占位字体样张代替最终验收。

阶段输入与整项验收依赖以 [父任务总表](../10-10-learn-v1/task-map.md) 为准；只完成阶段不能将整项标记完成。

## 交付步骤

- [ ] 验证最小 PDF 库及字体嵌入方式，记录选型证据。
- [ ] 实现布局到 PDF 的坐标、线型和字形绘制。
- [ ] 生成四模板及多页样张，检查 PDF 尺寸、字体及墨迹。

## 验收映射

- [ ] T09-AC1：页面真实尺寸正确，矢量格线完整，渲染器不自行分页。
- [ ] T09-AC2：指定字体、描红与中英数/拼音可绘制并嵌入；不使用占位字体冒充正式样张。
- [ ] T09-AC3：验证完整描边、字形外接边界、页数及云端包体/资源约束。

## 验证与收尾

- [ ] 按 docs/TESTING.md 对应章节执行模块与集成验证；创建模块后记录实际可运行命令，不预填不存在的 npm 脚本。涉及微信/CloudBase 的项目必须另有真实环境证据。
- [ ] 检查文档差异、相对引用及与 DECISIONS/PAPER_PRESETS 的一致性。
- [ ] 将本轮实际验证、失败原因与剩余项目记录到任务证据；必要时更新 TESTING/ROADMAP。
- [ ] 检查无正文、敏感凭据或未授权字体分发进入日志/提交。
- [ ] 独立检查通过后再标记完成，恢复/回退不得覆盖他人变更。

## 当前验收限制

PDF 可打开不代表授权、字形和实体打印已验收。
