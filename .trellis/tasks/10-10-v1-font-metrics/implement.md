# T04 执行清单

## 启动条件

- [ ] 核对 [PRD](prd.md)、[设计](design.md)、权威文档及本次工作区变更。
- [ ] 核对最终集成验收依赖（不等同于全部启动条件，分阶段输入见下文及父任务总表）：[T02 字体资源与授权验证](../10-10-v1-font-resources/prd.md)、[T03 完善通用文档与布局契约](../10-10-v1-document-contract/prd.md)

- [ ] 细化设计后完成执行前评审；按 Trellis 流程启动本子任务，不以父任务代替实现任务。

## 分阶段交付

A：T03 接口与可追溯本地字体候选齐备即可实现真实度量及测试向量；B：补跨端一致性、全部覆盖及适用许可。T02 未完成的正式分发审查不能被本地研发通过替代。

阶段输入与整项验收依赖以 [父任务总表](../10-10-learn-v1/task-map.md) 为准；只完成阶段不能将整项标记完成。

## 交付步骤

- [ ] 研究可供两端共用的最小度量实现和资源格式。
- [ ] 接入 measureTextMm 边界并标明字体/算法版本。
- [ ] 验证宽度精度、资源失败与真实字形边界的职责分离。

## 验收映射

- [ ] T04-AC1：英数、空格与组合字符使用真实字体数据，不使用固定字母宽度或每字母一格。
- [ ] T04-AC2：两端对同版输入产生相同度量，覆盖行尾临界位置。
- [ ] T04-AC3：字体或度量资源缺失/校验失败明确报错，不静默回退系统字体；描红不改变逻辑布局。

## 验证与收尾

- [ ] 在 `packages/paper-core` 执行 `npm test`（包含 TypeScript 编译）；缺依赖先 `npm install`。涉及布局时更新基准，并将渲染/实印剩余项交 T10。
- [ ] 检查文档差异、相对引用及与 DECISIONS/PAPER_PRESETS 的一致性。
- [ ] 将本轮实际验证、失败原因与剩余项目记录到任务证据；必要时更新 TESTING/ROADMAP。
- [ ] 检查无正文、敏感凭据或未授权字体分发进入日志/提交。
- [ ] 独立检查通过后再标记完成，恢复/回退不得覆盖他人变更。

## 当前验收限制

候选资源可用于开发验证；正式交付仍需 T02 授权结论及 T10 样张验收。
