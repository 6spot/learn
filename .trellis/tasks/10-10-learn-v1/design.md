# V1 交付边界与任务组织

## 架构基线

复用 ARCHITECTURE 的依赖方向：纸张核心输出确定性布局，Canvas/PDF 负责绘制；云端独立处理身份、额度、任务及文件访问。目录分工不等于部署多个服务。

```text
共享文本/字体度量/布局 → 本地 Canvas 预览
                    → 云端同版复算 → PDF → 私有存储
微信提交 → 可信身份/请求去重/预留 → 可靠执行交接 → 终态/账本事务
微信记录页 → 本人任务查询/鉴权领取
```

## 任务契约

- 本目录为父任务；25 个子任务分别负责独立交付。完整映射维护于 [task-map.md](task-map.md)。
- parent/children 只表示归属；依赖关系在总表及子任务 PRD/implement 中显式维护。
- T25 当前设计稿已按 D-043 接受为开发基线；其余子任务仍须按阶段细化真实接口与验证方案。设计文件是任务边界基线，不把批量创建文件或 HTML 稿当作功能完成。
- 现有规范初始化任务保持独立关联；未落地模块的规范以权威 docs 为依据，不编造现成代码示例。

## 共享协议与发布

T03 定义输入/可信预设/布局样式/错误，T04 提供共享度量，T07 先交协议再收齐四模板证据；T12 管理受支持组合和预设发布。T14 参数指纹仅用于幂等，不替代布局摘要、鉴权或正文归档。T14 持有受理响应边界，T15 持有执行接手/结算，双方联合验证交接窗口；T15/T16 遵守终态不反转和不自动重新排版。

T01 提供最小工程和验证宿主，T18 实现正式模板/编辑/预览，T19 的应用状态契约提前供页面消费。T21 是 P04/P05/P06 唯一界面所有者，T20 负责提交并进入共用 P06，不能各建一套结果页。T23.A 的生命周期设计提前供 T14/T17 使用，T23.B 最后完成真实清理集成；设计输入和最终集成依赖分层，避免假性循环。

先保留支持新旧组合的云端与资源，再发布客户端；新预设启用须有 T10 证据。旧资源退出不得影响在途任务。版本回退不反转业务终态。

## 优先验证的风险

1. T02 字体来源、授权及真实资源，T04/T10 完成度量和字形/打印。
2. T11 CloudBase 的可靠交接及平台载荷保留行为，验证 D-035 与 D-036 能同时满足。
3. T01 微信运行时兼容；T07/T19 版本过渡和本地输入保护。
4. T14～T17 的数据库事务/云存储故障窗口及权限。

仅技术可验证细节按证据推进；新的产品取舍先更新 DECISIONS 及其权威主题文档。
