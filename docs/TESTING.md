# 测试与验收标准

> 状态：验收框架。精确尺寸/公差以及模板支持矩阵必须通过 PoC 实测后补全。

## 1. 核心验证优先级

**先跑通纸张排版与打印，再叠加小程序、账户和商业化。** 第一阶段至少有能导出的纸张样张，不能只看界面效果就宣称已完成。

## 2. 纸张排版

- 以 [首版正式规格](PAPER_PRESETS.md) 为不可擅改的基准，按 [D-038](PAPER_PRESETS.md#21-中心线墨迹与打印安全区域d-038) 检查四种模板的中心线坐标、格宽/线距、完整行列/拼音线组数量、原点、几何留白与多页一致性。几何基准须锁定绝对位置及各中心线间距，不能只断言宽高和端点落在自身范围内。
- 墨迹验收与中心线几何测试分开：渲染接入后检查线宽、端点、拐角和字形的完整外接范围，不得按中心线区域裁掉半条外框；文字不能借描边余量越出书写区域。含墨迹的打印安全区域、线宽与测量公差仍待实际打印验证，不因几何测试通过而判定安全。
- 拼音 4 mm 组内线距、6 mm 相邻组边界线距均按中心线计量；线宽改变时几何仍固定，不能为保持 6 mm 墨迹净空而移动线组。打印按 A4、100% 实际大小，分别测中心线间距和墨迹边缘留白。
- D-038 本轮已补强 `geometry.test.mjs`：锁定四模板绝对原点/几何留白、三种方格的全部外部网格中心线及拼音 14 组坐标。本机 TypeScript 编译和全套 Node 测试 **22/22 通过**；仅更新基准及类型注释，几何算法和数值未改，未据此验证墨迹边界或实体打印。
- 规格已由 Owner 确认，**不等于实机打印验收已通过**；打印机安全边界、线宽与灰度仍应逐项测试。
- 当纸张尺寸无法整除格子时允许边缘余量；不得生成残格、强制压缩格宽或将格线绘至纸张之外。
- 标题居中、标题/正文间隔、段首两格、段落自动换行与强制换行区别。
- 正文未写满时剩余部分仍然是方格，不因文本长度裁掉网格。
- 输入或粘贴的单次显式换行开启新段并按该模板首行规则缩进；两次连续换行在段间额外保留一行空白；更多空行及跨页边界不应静默丢失。
- 自动折行属于原段，不再次缩进也不回写原文；独立标题块不应用正文首行缩进。
- 粘贴包含 LF、CRLF 的文字需保持空行及顺序；「整理换行」只能由用户主动触发，具体规则及撤销操作待交互设计确认。
- 标点（句号、逗号、括号、引号）、英文、数字、空格、emoji 组合字符、拼音声调。
- 英文和数字使用字体真实测量宽度占据连续格位，不能退化为每字母一格或固定字母数一格；测试中英数混排、单词行尾整体续行和 Canvas/PDF 字形度量一致。
- 英文单词放不下当前行时整体移至下一行；单词长度超过一整行时按完整字符边界分行。连续数字与小数点尽量整体排列，保留原文空格，不得越界、裁切、丢字或破坏 Unicode 组合字符。混合标点需另做边界验证。
- 方格行尾点号唯一策略：平常单独占格，紧跟行末最后一个汉字而无空格时与末格汉字共用一格；检查点号可读、不越界、无缺字，且没有自动后移汉字的第二策略。连续点号及引号需另设边界样例验证。
- 拼音用户直接输入：验证 `nǐ hǎo`、调号及 Unicode 组合字符、四线书写位置、音节换行；不可将汉字静默转换成猜测的拼音。
- 田字格中心虚线、米字格对角虚线、拼音四线三格线宽与打印清晰度。
- 无标题/正文时默认生成全页格线，无需选择空白；输入文字后默认填字；主动开启描红时在**相同文字定位与分页**上改为浅色参考字。描红模式没有文字时仍生成空白纸。
- 普通用户不选择空白/填字模式，也不调整字号或描红灰度。测试不同输入状态切换时预览/PDF 均保持一致，检查描红灰度、字形与格线在实际黑白打印下清晰可辨。
- 按 [D-031 字体分配表](PAPER_ENGINE.md#首版字体分配与描红d-031) 验收四模板的填字/描红：作文方格描红沿用 MiSans 且仅改浅灰；田字格/米字格中文描红使用浅灰霞鹜文楷 GB；拼音填字与描红均使用 MiSans Latin、描红仅改浅灰。字号沿用对应填字预设，字体加载、PDF 嵌入和实际灰度仍待验证。
- 对照同一内容开启/关闭描红时的布局基准，在**字体不同**的情况下仍应保持同一逻辑占位、换行与分页，字形不得溢出预设格位；正式渲染接入后须按分配表生成对应样张并实印验收。
- 常用小学汉字笔画、点钩折、字形结构需人工评估，霞鹜文楷 GB 不得未经验证便称为规范书写教学字体；核对 OFL 附带要求及 MiSans PDF 嵌入、子集化/客户端资源分发的使用许可。
- 长文章跨页及末页余格；任何内容均不得静默截断，超过产品限制的输入必须明确告知。

以之前实际制作的 9 月 28 日、9 月 29 日两篇作文为第一批回归样例，不默认公开用户作文原文；样本如纳入仓库须先确认可用内容。

### 2026-10-10 A4 文字排版占位字体试验

本轮在仓库外生成了一份五页 A4 矢量 PDF，用于**格线物理规格、基础文字占位与分页的早期目视检查**：作文方格 2 页（标题、段落、中英数和续页）、田字格填字 1 页、米字格浅灰描红 1 页、拼音四线三格 1 页。经 PDF 页面尺寸检查，全部 5 页均为 A4（约 595.28 × 841.89 pt）；已渲染成 PNG 进行视觉检查，字体在 PDF 中可嵌入。

**这不是正式字体样张，也不是项目引擎已完成的证据。** 因执行环境无法获取 MiSans 和霞鹜文楷 GB 官方字体文件，本轮使用系统已有的 AR PL 字体作**明确注明的占位字体**，PDF 每页也有非正式字体标记。示例文字定位脚本仅属临时验证，不能代替预定的纯 TypeScript 布局内核；它对复杂标点、英文间距、Unicode 边界与拼音书写基线尚不具正式正确性保证。

后续必须使用官方实际字体重新生成同结构样张，核对 MiSans 的字体嵌入/子集化许可、霞鹜文楷 GB 规范书写字形、字号、描红灰度、拼音声调和各字体在固定格位内的边界。**本轮不关闭字体/分页相关待测项目，也不据此宣布物理打印验收通过。**

### 2026-10-10 纯 TypeScript 格线几何阶段结果

- 新建 `packages/paper-core`：纯 TS A4 模板几何库，无微信、CloudBase、Canvas、PDF 或字体依赖；固定规格来源为 [PAPER_PRESETS](PAPER_PRESETS.md)，预设版本标记 `v1-design` 表示 Owner 确认设计但尚未完成实体打印验收。
- 产生带物理毫米单位的 `PageGeometry`（完整线段、边界、模板与版本号），四种模板均按确认位置创建完整网格或 14 组拼音线；不裁残格，不改变预设格宽，非法参数直接抛错。
- 本地运行 TypeScript 编译与 Node 内建测试，**7/7 通过**：四种 A4 规格与线条数量、拼音四线组间距、输入不可变与几何无效值校验。
- **尚未实现**：文字内容布局、中文标点、英文测量、标题缩进、分页、描红渲染、真正字体嵌入、Canvas 和 PDF 输出。这一阶段不应被描述为完整纸张引擎、用户端到端闭环或打印验收。

`cd packages/paper-core && npm install && npm test` 可重现基础检查（需要 Node 与 npm）。

## 3. 输出兼容性

| 目标 | 必测 |
|---|---|
| Canvas | 纸张比例正确、缩放不改物理数据、分页稳定、手机性能 |
| PDF | 标准页面尺寸、文字字形、字体嵌入、微信打开、真实打印测量 |
| 跨输出 | Canvas 预览和 PDF 的页数、格线几何、文本占格规则一致 |

按 [D-032 版本匹配规则](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032) 增加以下验收（**待实现、待验证**）：

- 相同内核、预设和字体/度量资源组合在微信端与云端产生一致的布局摘要；重点覆盖英数临界换行、多页、Unicode 组合字符及描红，最终字形仍需单独验收。
- 小程序或云端仅更新无关业务/UI 时，排版版本组合不变仍可生成；内核、预设或字体/度量资源任一项变化时，必须校验新组合，不能仅凭预设版本相同放行。
- 发布新版、切换 active 预设时，已锁定且仍受支持的旧组合继续用于编辑和生成；进行中任务不因部署或资源清理改用新版本。
- 不支持的组合、资源加载/校验失败、伪造版本、布局摘要不一致均明确阻止导出且不扣次；保留当前输入，更新或恢复资源后重新预览。不能用系统字体或最新预设静默兜底。
- 客户端伪造摘要不能绕过云端重新布局、参数与额度校验；摘要比较不向日志写入正文或文字布局数据。

按 [D-033 微信更新流程](ARCHITECTURE.md#32-不受支持版本的微信更新流程d-033) 验证以下场景（**待实现、待真机验证**）：

- 打开小程序时由应用入口统一检查、缓存并合并请求；冷启动不因 `onLaunch`/`onShow` 重复发请求，页面切换不重复检查或注册更新监听，短时间反复回前台不重复弹窗。提交生成仍由云端校验；业务检查网络失败不误判版本不受支持。
- 仍受支持的旧内核不因发布号不同而被要求更新，不受支持的内核阻止新生成且不扣次；仍可安全使用的历史查询及有效文件领取不被无故阻断。
- `hasUpdate` 为真但未收到 `onUpdateReady` 时不调用 `applyUpdate`；更新就绪且用户主动操作后才重启，已有正文时不直接强制重启或默认持久化正文。
- 无可用更新、下载失败、用户暂不更新时均保留当前输入且不循环重启；重启后重新验证版本并预览。
- 当前内核支持的新预设/字体资源只需加载和重新预览；资源加载失败、布局摘要不一致不误触发代码更新。

首版不开发 DOCX，界面不展示 Word 导出；如后续启用需另行制定 WPS/Word 可编辑性测试。

## 4. 云端生成与额度

- 按 [D-037](DATA_AND_CREDITS.md#44-请求号参数指纹与幂等d-037) 验证双击、网络重试沿用原请求号与参数，同号同参并发只建立一个任务、一份预留及一次成功消费；查询和重复领取不重新渲染。
- 相同请求号改动标题/正文、空格/空行、描红、允许的文字设置或任一排版版本时明确拒绝，不覆盖原任务、不返回旧文件、不自动新建任务；主动使用新号提交相同内容则可形成新任务。
- 不同用户即使使用相同请求号也独立处理，不能读取对方任务；云端自行计算带密钥参数指纹，校验字段/规范化版本及密钥轮换兼容性，不信任客户端摘要替代校验。
- 请求号、任务号及指纹能支持响应丢失后的查询，不依赖持久化正文；任务、指纹清理和过期重试按 O-007 定稿后验证，清理不能导致旧重试再次扣次。
- 双击和并发请求不能使额度变负。
- 模板/参数/内容无效的请求不扣次。
- 按 [D-034](DATA_AND_CREDITS.md#4-可信任务状态机d-034) 验证成功、失败与额度流水原子结算，预留阶段执行交接失败/超时也能释放；重复回调/对账不重复扣次或返还。
- 成功提交与超时处理并发时只允许一次有效结算；任务已失败后迟到上传不交付、不重新扣次，任务已成功后迟到的失败处理不退款，旧执行批次不能完成新批次的任务。
- PDF 上传成功但状态事务失败、事务成功但响应丢失时可对账收敛；清理孤立/迟到产物不能误删已被成功任务引用的文件。
- 按 [D-036](DATA_AND_CREDITS.md#43-不保存正文的恢复边界d-036) 验证恢复器仅查询、核验已有产物并结算/释放，不调用渲染器重做，不为重试保存正文或含原文的布局快照。
- 云端执行中断且无完整产物时确认失败并释放预留；仍在有效执行、暂未出现文件或一次存储查询失败不误判任务失败。已有产物只在完整性/任务关联可验证、批次期限有效且任务未结束时补完成功结算，过期或已失败任务不复活。
- 失败后用户重新提供输入创建新任务；当前编辑器内容仍在时可复用，历史记录不提供恢复原文或无输入重做。重复查询及结算事务重试保持幂等，不重复扣次。
- 按 [D-035](PRODUCT.md#41-生成记录与离页体验d-035) 验证已受理任务在切换页面、停止轮询、关闭/更新重启小程序后仍由云端推进或按规则终结；客户端等待超时/断网不直接判失败或退款。
- 响应丢失时使用原请求查询受理结果，不误报已提交、不自动创建第二个任务；重新进入“我的 → 生成记录”能看到本人的进行中、成功、失败和文件过期信息。
- 记录/详情仅在可见且有未结束任务时适度刷新，离页/后台停止页面轮询，重新进入查询最新状态；历史元数据不保存正文或输入标题，不宣称可以恢复编辑草稿。
- 同一任务重复领取 PDF 不再计次。
- 文件过期只改变交付可用性，不把成功任务改为失败或自动重新生成；历史列表、详情及领取文件均校验归属，跨用户访问、身份注销遵循访问控制。

## 5. 权限、支付与运营

- 普通用户绕过页面路由也无法读取管理接口或编辑别人的额度。
- 数据库不允许客户端任意读写账本及管理员配置。
- 付费和广告开通后：重复平台通知不重复发放；退款能对账；失败订单不发放额度。
- 统计 DAU、任务数、错误率及额度消耗和原始有效记录对得上；重试不双计。
- 个人信息和用户正文不出现在应用日志、统计事件及错误上报中。

## 6. 最小上线检查

UI 验收同时核对 D-039 的组件策略及 [UI_DESIGN](UI_DESIGN.md) 经评审确认的页面/菜单/样式：设计稿状态须明确，HTML 原型不能替代微信真机。检查页面路由、主次操作、原生控件语义、键盘/安全区、大字号、异步状态、更新提示和返回时的内存输入行为。

完成核心模板和打印样张验收；云端配置不泄露密钥；正式和测试环境隔离；配置用量告警；隐私及用户数据清理规则一致；管理员权限实际测试；发布前检查微信相关资质和 API 可用性。

**当前已有纯 TypeScript 几何与基础方格文字布局的测试记录（见上方阶段结果），但这些不证明微信端、云函数、正式字体、PDF、计次或家庭实际打印已通过。** 未完成的验收项仍以本文相应检查点为准。
