# 测试与验收标准

> 状态：验收框架。精确尺寸/公差以及模板支持矩阵必须通过 PoC 实测后补全。

## 1. 核心验证优先级

**先跑通纸张排版与打印，再叠加小程序、账户和商业化。** 第一阶段至少有能导出的纸张样张，不能只看界面效果就宣称已完成。

## 2. 纸张排版

- 以 [首版正式规格](PAPER_PRESETS.md) 为不可擅改的基准，检查四种模板真实尺寸、格宽、完整行列/拼音线组数量、定位原点、边距与多页一致性。
- 规格已由 Owner 确认，**不等于实机打印验收已通过**；打印机安全边界、线宽与灰度仍应逐项测试。
- 当纸张尺寸无法整除格子时允许边缘余量；不得生成残格、强制压缩格宽或将格线绘至纸张之外。
- 标题居中、标题/正文间隔、段首两格、段落自动换行与强制换行区别。
- 正文未写满时剩余部分仍然是方格，不因文本长度裁掉网格。
- 输入或粘贴的单次显式换行开启新段并按该模板首行规则缩进；两次连续换行在段间额外保留一行空白；更多空行及跨页边界不应静默丢失。
- 自动折行属于原段，不再次缩进也不回写原文；独立标题块不应用正文首行缩进。
- 粘贴包含 LF、CRLF 的文字需保持空行及顺序；「整理换行」只能由用户主动触发，具体规则及撤销操作待交互设计确认。
- 标点（句号、逗号、括号、引号）、英文、数字、空格、emoji 组合字符、拼音声调。
- 英文和数字使用字体真实测量宽度占据连续格位，不能退化为每字母一格或固定字母数一格；测试中英数混排、单词行尾整体续行和 Canvas/PDF 字形度量一致。
- 英文单词放不下当前行时整体移至下一行；单词长度超过一整行时按完整字符边界分行。连续数字与小数点尽量整体排列，保留原文空格，不得越界、裁切、丢字或破坏 Unicode 组合字符。混合标点需另做边界验证。
- 方格行尾点号唯一策略：平常单独占格，紧跟行末最后一个汉字而无空格时与末格汉字共用一格；检查点号可读、不越界、无缺字，且没有自动后移汉字的第二策略。连续点号及引号需另设边界样例验证。
- 拼音用户直接输入：验证 `nǐ hǎo`、调号及 Unicode 组合字符、四线书写位置、音节换行；不可将汉字静默转换成猜测的拼音。
- 田字格中心虚线、米字格对角虚线、拼音四线三格线宽与打印清晰度。
- 无标题/正文时默认生成全页格线，无需选择空白；输入文字后默认填字；主动开启描红时在**相同文字定位与分页**上改为浅色参考字。描红模式没有文字时仍生成空白纸。
- 普通用户不选择空白/填字模式，也不调整字号或描红灰度。测试不同输入状态切换时预览/PDF 均保持一致，检查描红灰度、字形与格线在实际黑白打印下清晰可辨。
- 首版字体验收：MiSans 普通填字、霞鹜文楷 GB 中文描红、MiSans Latin 拼音；在**字体不同**的情况下仍应保持同一逻辑占位、换行与分页，字形不得溢出预设格位。
- 常用小学汉字笔画、点钩折、字形结构需人工评估，霞鹜文楷 GB 不得未经验证便称为规范书写教学字体；核对 OFL 附带要求及 MiSans PDF 嵌入、子集化/客户端资源分发的使用许可。
- 长文章跨页及末页余格；任何内容均不得静默截断，超过产品限制的输入必须明确告知。

以之前实际制作的 9 月 28 日、9 月 29 日两篇作文为第一批回归样例，不默认公开用户作文原文；样本如纳入仓库须先确认可用内容。

## 3. 输出兼容性

| 目标 | 必测 |
|---|---|
| Canvas | 纸张比例正确、缩放不改物理数据、分页稳定、手机性能 |
| PDF | 标准页面尺寸、文字字形、字体嵌入、微信打开、真实打印测量 |
| 跨输出 | Canvas 预览和 PDF 的页数、格线几何、文本占格规则一致 |

首版不开发 DOCX，界面不展示 Word 导出；如后续启用需另行制定 WPS/Word 可编辑性测试。

## 4. 云端生成与额度

- 相同幂等请求重复提交只发生一次消费。
- 双击和并发请求不能使额度变负。
- 模板/参数/内容无效的请求不扣次。
- 生成失败能够释放预留；函数超时最终能恢复或对账。
- 同一任务重复领取 PDF 不再计次。
- 文件过期、跨用户下载、身份注销都遵循访问控制。

## 5. 权限、支付与运营

- 普通用户绕过页面路由也无法读取管理接口或编辑别人的额度。
- 数据库不允许客户端任意读写账本及管理员配置。
- 付费和广告开通后：重复平台通知不重复发放；退款能对账；失败订单不发放额度。
- 统计 DAU、任务数、错误率及额度消耗和原始有效记录对得上；重试不双计。
- 个人信息和用户正文不出现在应用日志、统计事件及错误上报中。

## 6. 最小上线检查

完成核心模板和打印样张验收；云端配置不泄露密钥；正式和测试环境隔离；配置用量告警；隐私及用户数据清理规则一致；管理员权限实际测试；发布前检查微信相关资质和 API 可用性。

**当前还未有任何 PoC 或自动化测试结果；本文列的是应做的检查，不代表已通过。**
