# 纸张模板与统一排版引擎

> 状态：核心技术设计草案；未运行 PoC。本文首先规定边界与要验证的问题，不假定所有模板都有相同的 Word 编辑能力。

## 1. 目标

给定同一份纸张描述，输出稳定、可打印的几何布局，首版通过 Canvas 和 PDF 表达，DOCX 仅作为以后可能增加的适配器。模板只定义纸张结构与默认配置，不独占标题、缩进或换行等文字能力。内容是可排列的文本块；通用文字排版规则负责对齐、缩进、自动换行与分页；布局层确定物理坐标；渲染层只负责呈现。完整格线覆盖可打印内容区域是所有纸张模板的固定规则，不是可选开关。

```text
PaperDocument
  ├── pageSpec                 纸张与边距
  ├── templateId/version       模板和版本
  ├── templateOptions          格线、格宽、颜色等
  ├── textStyles               通用标题/段落排版规则
  └── content                  空白 / 填字 / 描红 + 文本块
           │
           ▼
      validate + layout
           │
           ▼
      LayoutPages
           ├── 页面物理尺寸
           ├── 格线/路径集合
           ├── 字形坐标与占格映射
           └── 分页和块结构
              │
       ┌──────┴──────┐
       ▼             ▼
     Canvas          PDF
   （本地预览）    （正式打印）
```

## 2. 输入与输出契约（提议）

**输入** `PaperDocument`：
- `templateId` 和 `templateVersion`：标识确定版本的模板定义；
- `pageSpec`：在产品提供的固定纸张规格预设中选择（如 A4 及经验证的常用尺寸/方向）；包含预设的打印安全边距；**不允许任意放大纸张，也不提供是否整页铺格的开关**。
- `templateOptions`：从模板已验证的版式预设取得格宽/高、行列数、间距、线型、辅助虚线、颜色与粗细；首版不开放能破坏完整格线和安全边界的自由尺寸设置。
- `content.mode`：`blank | filled | tracing`；
- `content.blocks`：可选标题与正文等逻辑文本块；不将原文件的视觉折行默认为段落；
- `textStyles` / 文本块规则：水平对齐（如居中）、首行缩进（如按两个字符格）、自动换行、手动段落/换行、行距等通用排版参数；所有具备文字承载区域的模板都可以使用，而非作文格专属。具体单元度量按格线结构适配。

**输出** `LayoutPages`：按页包含可定位的线段/路径/网格/文字对象和物理尺寸、分页信息、文本单元到格子的映射。建议坐标统一用**毫米**，渲染边界换算为 Canvas 像素、PDF pt；毫米是建议而非已最终确认的协议。

PDF 与小程序预览应消费同一份布局结果；字体和绘制差异须由样张与打印结果验证，不能自行改变格宽、换行和分页。

## 3. 模板、文字排版、内容分别独立

**模板不是一套封闭功能**，它定义格线结构、可放置文字的区域、默认参数，以及该结构如何解释“一个位置/一行”。以下仅列默认预设，不限制其它文本排版能力的使用：

| 模板 | 格线结构 | 默认呈现（可调整） |
|---|---|---|
| 作文方格 | 方格 | 可选标题居中；正文首行空两格、自动换行 |
| 田字格 | 方格 + 中心横竖辅助线 | 空白/单字练习；也允许标题、段首缩进、连续文字和自动换行 |
| 米字格 | 田字格 + 对角辅助线 | 空白/单字练习；也允许标题、段首缩进、连续文字和自动换行 |
| 拼音四线三格 | 四线三格的行带 | 拼音排版；对齐、缩进、换行等通用规则仍可用，但以文本行带而非字符方格计量 |
| 组合及其他 | 多个格线区域 | 复用通用文字规则，各区域定义自身承载与位置映射 |

**通用文字排版能力**（与模板解耦）：

- **文本块**：标题、正文段落；标题并非作文格特有，用户可为任何模板添加。
- **水平对齐**：左、居中、右；“标题居中”只是对标题块采用居中策略。
- **首行缩进**：每段可配置，以相关文字布局单位衡量；方格类可以空两个格，行带类按行带上的字符排版尺度转换。
- **自动换行**：在内容区域的剩余位置不足时自然续行；适用于田字格、米字格及其他可填字模板，而不是作文格专属。
- **显式段落/换行**：逻辑段落独立于原始文件的视觉换行；具体导入时怎样识别需要后续验证。
- **内容模式**：空白、填字、描红。填字与描红共享基础定位机制，但具体字形绘制策略可不同。

**模板预设提供开箱即用的组合**，如作文格默认居中标题和两格首行缩进，田字格默认空白练习；所有适用模板都能复用文字能力。用户端默认只显示内容模式/输入与生成，少量安全选项按需展开；不展示具体格宽、行列、边距参数。

**格线类型/排版算法由代码定义，规格与默认值由后台统一维护。** 后台可发布已验证的标准版式预设，小程序不需要更新代码才能获取当前发布的规格；但格线算法发生变化仍需要代码更新。首版不需要大型模板 CMS。后台预设如何存储、审核与发布仍需做最小实现选择。

## 4. 完整铺格与作文样例规则

### 4.1 固定纸张规格与完整、安全的铺格

1. 首版只提供**预先设计、计算并验证的固定纸张/版式预设**，例如 A4 作文格和常用田字格规格。每个预设明确纸张物理尺寸、方向、安全边距、单元宽高、列数、行数、基准点和格线粗细。具体尺寸/行列数留待打印样张验证后确定，不使用随意凑出的数字。
2. **先在安全区域内生成完整格线，再放文字**。没有“铺满/不铺满”选项；铺格范围是预设的完整书写区域，而不是要求边框延伸到纸张裁切边缘。
3. **宁留白，不截断**：可用尺寸无法整除完整格子时，保留边缘余量，必要时左右/上下对称分配；不绘制残格、不越过安全边距、不强制缩放既定格宽、不裁掉末端内容。
4. 标题、正文和空白内容使用同一张完整铺格的底纸。文字不能溢出格线或纸张安全边界；行尾文字、标点如不能合法放下应合理换行，而不是裁切。
5. 一页装不下的正文继续生成同样完整铺格的新页面，绝不能因为超过固定行列数而静默丢失。超过产品明确限制的极长内容，应在生成前说明限制并拒绝/引导拆分，不能返回不完整文件。
6. 小程序预览与 PDF 均使用同一组经验证的物理布局参数；预览缩放只改变屏幕显示比例，不改变打印尺寸。

### 4.1.1 建议的预设几何数据

```ts
type PaperPreset = {
  pageSizeMm: { width: number; height: number };
  orientation: "portrait" | "landscape";
  safeMarginsMm: { top: number; right: number; bottom: number; left: number };
  layout: {
    unitWidthMm: number;
    unitHeightMm: number;
    rows: number;
    columns: number;
    originMm: { x: number; y: number };
  };
};
```

此结构是示意，不要求所有线格都使用行列单元：横线纸和拼音行带需定义相应的固定周期/基线。模板不能为容纳内容而改变物理参数。

### 4.1.2 后台维护的预设与少量用户可改项

用户只选择**已发布的版式预设**（例如常规版/大格版），不得传入自定义行列、任意格宽或负边距等未经验证的物理参数。后台维护每种预设的纸张尺寸、格线周期、行列/行带数量、安全边距、定位原点、线条默认样式及可选的文字预设；用户可以保留默认值直接生成。

建议把设置分成：
- **后台专业配置**：格线几何、页边距、可打印范围、可选预设和默认预设；变更必须先检查物理边界并打印验证。
- **普通用户基本输入**：空白/填字/描红及相应标题和正文。
- **少量按需展开的安全设置**：标题对齐、首行缩进、预设规格切换、经验证的颜色/描红深浅范围。自然换行与自动分页是固定能力，不提供关闭开关。

为避免用户正在预览时后台修改规格导致导出不一致，**建议**每份预设含稳定的 `presetId` 和发布版本；预览和云端生成须绑定同一发布版本，云端重新按该版本布局/校验，不接受客户端自报的行列或物理尺寸。后台编辑先形成新版本，验证后再发布；旧生成任务仍使用原有版本。具体存储与发布接口待下一轮技术设计。

### 4.2 作文预设（可在其他格子模板复用）

根据此前两篇 Word 作文的转换经验，作文格**默认**使用：
- 标题居中，标题与正文之间可空行；
- 首行空两格，正文按逻辑段落自然换行；
- 汉字、数字、标点按确定的占格规则放置；中文标点默认占独立格；
- 多页按统一尺寸、边距和格子位置排版。

这些都是通用文字排版能力的参数组合，而不是作文模板独有的实现。田字格或米字格使用相同排版选项时也应得到同等的标题/段落行为。

文字处理需要特别测试：中文引号/括号/句号的禁则、连续数字、英文单词、空格、全角/半角、拼音声调、表情及 Unicode 组合字符。**不能用 `str[i]` 直接将 UTF-16 代码单元当作完整文字。** 英文单词怎样分格、标点禁则的优先级仍属待决。

## 5. 首版输出：Canvas 预览 + PDF 打印

### Canvas：小程序本地预览

根据 `LayoutPages` 在微信端渲染，保持纸张真实宽高比。放大/缩小只影响显示；不修改格宽和分页；预览不调用生成云函数，不扣次数。

### PDF：唯一正式导出格式

CloudBase 云函数根据同一份布局生成 PDF。它是首版打印交付物，必须验证：
- 页面的真实物理尺寸和固定安全边距；
- 格线完整且没有任何跨界、遮挡或裁切；
- 标题、正文、标点及拼音的文字位置，长文自动续页；
- 中文字体可用性、授权、必要的嵌入、缺字处理与文件大小；
- 微信打开和实际打印（避免打印对话框“适合页面”二次缩放造成测量误差）。

### DOCX：后续可选的兼容性工作

**首版不开发、不承诺 Word 下载。** 将来若真实用户需要编辑，再验证 WPS/Microsoft Word 原生对象的编辑、分页及复杂格线表达能力。不要将整页截图包装为“可编辑 Word”。排版核心不依赖 DOCX，因此未来增加导出适配器无需改变页面规则。

## 6. 正确性与一致性

不要求跨渲染器像素级一致；需要：
- A4 等物理尺寸正确，打印为 100% 比例时格宽及边距符合公差；
- 页数、行列位置、正文占格和分页符合规范；
- 首版只提供 PDF 下载，不在页面显示尚未支持的 Word 入口；
- 所有调整能复用同一套测试样本，避免“改作文格影响米字格”。

初步公差及样张尺寸将在 PoC 期间确定，不能凭空规定毫米级指标却不实测。

## 7. 技术验证顺序（下一轮讨论重点）

1. 为首批常用纸张制定固定尺寸/版式预设，计算完整格线与余量，再实际打印确认。
2. 确定通用文字块的对齐、缩进、自动换行、标点、空格、英文和段落规则，验证作文格/田字格/米字格可共享。
3. 做 A4 整页作文格两页样张，与原始两篇作文效果对照。
4. 做田字格、米字格、拼音格 PDF 样张，检查辅助线/虚线。
5. 以 PDF 为主要交付样张，检查安全留白、溢出续页及没有内容截断。
6. 确定测试向量、字体方案，再连接微信预览与云函数。
