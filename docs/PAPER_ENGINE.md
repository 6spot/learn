# 纸张模板与统一排版引擎

> 状态：核心技术设计草案；未运行 PoC。本文首先规定边界与要验证的问题，不假定所有模板都有相同的 Word 编辑能力。

## 1. 目标

给定同一份纸张描述，输出稳定、可打印的几何布局，再通过 Canvas、PDF、DOCX 三种方式表达。模板只定义纸张结构与默认配置，不独占标题、缩进或换行等文字能力。内容是可排列的文本块；通用文字排版规则负责对齐、缩进、自动换行与分页；布局层确定物理坐标；渲染层只负责呈现。完整格线覆盖可打印内容区域是所有纸张模板的固定规则，不是可选开关。

```text
PaperDocument
  ├── pageSpec                 纸张与边距
  ├── templateId/version       模板和版本
  ├── templateOptions          格线、格宽、颜色等
  ├── textStyles               通用标题/段落排版规则
  └── content                  空白 / 填字 / 描红 + 文本块
           │
           ▼
      validate + layout
           │
           ▼
      LayoutPages
           ├── 页面物理尺寸
           ├── 格线/路径集合
           ├── 字形坐标与占格映射
           └── 分页和块结构
              │
       ┌──────┼────────┐
       ▼      ▼        ▼
     Canvas  PDF      DOCX
```

## 2. 输入与输出契约（提议）

**输入** `PaperDocument`：
- `templateId` 和 `templateVersion`：标识确定版本的模板定义；
- `pageSpec`：A4/A5 等尺寸、横/竖、打印安全边距；**不提供是否整页铺格的选项**，格线默认覆盖整个有效排版区域；
- `templateOptions`：格宽/高、格间距、线型、辅助虚线、线颜色与粗细；
- `content.mode`：`blank | filled | tracing`；
- `content.blocks`：可选标题与正文等逻辑文本块；不将原文件的视觉折行默认为段落；
- `textStyles` / 文本块规则：水平对齐（如居中）、首行缩进（如按两个字符格）、自动换行、手动段落/换行、行距等通用排版参数；所有具备文字承载区域的模板都可以使用，而非作文格专属。具体单元度量按格线结构适配。

**输出** `LayoutPages`：按页包含可定位的线段/路径/网格/文字对象和物理尺寸、分页信息、文本单元到格子的映射。建议坐标统一用**毫米**，各渲染器在边界转换为 Canvas 像素、PDF pt、Word twip 等目标单位；毫米是建议而非已最终确认的协议。

无论 PDF、DOCX、预览，布局规则的决策只执行一次；不同渲染器允许因字体与目标文档模型差异存在有限的偏差，需通过验收标准界定。

## 3. 模板、文字排版、内容分别独立

**模板不是一套封闭功能**，它定义格线结构、可放置文字的区域、默认参数，以及该结构如何解释“一个位置/一行”。以下仅列默认预设，不限制其它文本排版能力的使用：

| 模板 | 格线结构 | 默认呈现（可调整） |
|---|---|---|
| 作文方格 | 方格 | 可选标题居中；正文首行空两格、自动换行 |
| 田字格 | 方格 + 中心横竖辅助线 | 空白/单字练习；也允许标题、段首缩进、连续文字和自动换行 |
| 米字格 | 田字格 + 对角辅助线 | 空白/单字练习；也允许标题、段首缩进、连续文字和自动换行 |
| 拼音四线三格 | 四线三格的行带 | 拼音排版；对齐、缩进、换行等通用规则仍可用，但以文本行带而非字符方格计量 |
| 组合及其他 | 多个格线区域 | 复用通用文字规则，各区域定义自身承载与位置映射 |

**通用文字排版能力**（与模板解耦）：

- **文本块**：标题、正文段落；标题并非作文格特有，用户可为任何模板添加。
- **水平对齐**：左、居中、右；“标题居中”只是对标题块采用居中策略。
- **首行缩进**：每段可配置，以相关文字布局单位衡量；方格类可以空两个格，行带类按行带上的字符排版尺度转换。
- **自动换行**：在内容区域的剩余位置不足时自然续行；适用于田字格、米字格及其他可填字模板，而不是作文格专属。
- **显式段落/换行**：逻辑段落独立于原始文件的视觉换行；具体导入时怎样识别需要后续验证。
- **内容模式**：空白、填字、描红。填字与描红共享基础定位机制，但具体字形绘制策略可不同。

**模板预设只提供开箱即用的组合**，如作文格默认居中标题和两格首行缩进，田字格默认单字练习；用户在相应模式中仍能调整、启用和复用相同的排版能力。界面可以按内容模式与使用频率折叠选项，但不得因模板类型硬编码屏蔽通用文字规则。

模板定义建议为代码中的声明式数据，不需要为静态模板开发云端 CMS。

## 4. 完整铺格与作文样例规则

### 4.1 所有纸张的固定铺格规则

1. **先铺满整页有效排版区域，再放文字**。没有“整页铺满/仅按内容绘制”的切换选项。
2. “铺满”指在扣除打印安全边距后，重复格线/行带填满可用范围；即使完全空白，整页也保留纸张模板。
3. 当有效区域与单元尺寸不整除时，如何分配余量（两侧对称边距、单元间距等）需通过样张确认；不得生成越界的残缺格或悄悄缩放既定格宽。
4. 标题和正文只是覆盖在格线上的内容，不改变格线是否存在；多页继续遵循相同铺格规则。

### 4.2 作文预设（可在其他格子模板复用）

根据此前两篇 Word 作文的转换经验，作文格**默认**使用：
- 标题居中，标题与正文之间可空行；
- 首行空两格，正文按逻辑段落自然换行；
- 汉字、数字、标点按确定的占格规则放置；中文标点默认占独立格；
- 多页按统一尺寸、边距和格子位置排版。

这些都是通用文字排版能力的参数组合，而不是作文模板独有的实现。田字格或米字格使用相同排版选项时也应得到同等的标题/段落行为。

文字处理需要特别测试：中文引号/括号/句号的禁则、连续数字、英文单词、空格、全角/半角、拼音声调、表情及 Unicode 组合字符。**不能用 `str[i]` 直接将 UTF-16 代码单元当作完整文字。** 英文单词怎样分格、标点禁则的优先级仍属待决。

## 5. 三种渲染输出

### Canvas：小程序预览

在微信本地根据 `LayoutPages` 绘制，尺寸随屏幕缩放但仍保留纸张真实宽高比。放大/缩小只影响展示视口。预览不需要走云函数，也不扣次数。

### PDF：打印几何基准

在 CloudBase 云函数中将同一布局转换为 PDF 纸张尺寸、格线、文字。需验证中文字体的版权授权、云端嵌入/子集、字形缺失、文件大小及微信预览能力。以实际 A4 打印为基准，不能仅看手机缩略图。

### DOCX：可编辑输出

通过文档表格、边框、段落等 **真实 Word 对象** 表达。初期可考虑 JS/TS `docx` 库，但必须测 WPS 与 Microsoft Word 的换页、行高、边框和表格编辑能力。

对于米字格斜线、拼音格等复杂模板，不能保证原生 Word 结构均能精确表达；模板应有显式 DOCX 能力标记。未通过验证的模板只提供 PDF，**不能以整页截图假装 Word 可编辑**。

## 6. 正确性与一致性

不要求跨渲染器像素级一致；需要：
- A4 等物理尺寸正确，打印为 100% 比例时格宽及边距符合公差；
- 页数、行列位置、正文占格和分页符合规范；
- PDF/Word 的适用能力和限制向用户真实呈现；
- 所有调整能复用同一套测试样本，避免“改作文格影响米字格”。

初步公差及样张尺寸将在 PoC 期间确定，不能凭空规定毫米级指标却不实测。

## 7. 技术验证顺序（下一轮讨论重点）

1. 定义首批纸张和默认物理格宽、边距、分页。
2. 确定通用文字块的对齐、缩进、自动换行、标点、空格、英文和段落规则，验证作文格/田字格/米字格可共享。
3. 做 A4 整页作文格两页样张，与原始两篇作文效果对照。
4. 做田字格、米字格、拼音格 PDF 样张，检查辅助线/虚线。
5. 验证 DOCX 在 WPS/Word 的真实编辑能力；根据结果标注各模板支持情况。
6. 确定测试向量、字体方案，再连接微信预览与云函数。
