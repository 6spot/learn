# 系统架构

> 状态：架构基线；`packages/paper-core` 已有 A4 格线和部分方格文字布局源码，其他目录主要是拟定职责，并非全部已经实现。2026-10-10。

## 1. 组件及数据流

```text
微信原生小程序（WXML / WXSS / TypeScript）
 ├─ 普通入口：模板目录 → 编辑 → Canvas 预览 → 生成 / 下载
 ├─ 我的：身份、生成次数、记录
 └─ 管理入口：运营聚合数据（仅 Owner）
       │
       ├─ 本地：模板参数 / 纯 TS 布局计算 / Canvas 渲染
       │
       └─ wx.cloud.callFunction
                 │
      关联的微信云开发 / CloudBase 环境
       ├─ API 云函数：可信身份、额度、任务、统计、管理权限
       ├─ Render 云函数：PDF 生成与文件交付
       ├─ 数据库：账户、额度流水、任务、统计、配置
       └─ 云存储：短期生成文件（生命周期清理）
                 │
      CloudBase 控制台：运行日志、监控、数据库和管理
```

不使用自建 VPS / EdgeOne / 独立 Web 后台。小程序直接调用关联云开发环境；如果今后增加非微信客户端，再评估其他接入方式。

## 2. 两类不同的边界

**业务边界**：通用能力（身份、权益、订单、广告奖励、统计、运营）与首个工具域（学习纸张）分开。未来其他工具不应被迫遵循 `PaperDocument` 结构。

**技术边界**：纸张格线定义（模板）≠ 通用文字排版规则（标题、对齐、缩进、换行）≠ 布局计算 ≠ 绘制/导出 ≠ 云端业务编排。模板只提供默认参数组合，不拥有专属的文本排版实现。整页有效排版区域铺满格线是固定布局规则，不提供开关。用户无需选择空白/填字：引擎依内容自动判定；描红需要主动开启，且与正常填字共用布局，仅渲染样式不同。

布局引擎输入标准化纸张文档，结合**后台统一维护、每种模板唯一生效的固定纸张规格（有版本号）**、通用文字块规则和内容，输出与运行时无关的几何场景；首版 Canvas/PDF 渲染器分别消费它，不应自行决定分页或段首规则。田字格、米字格与作文格都能使用通用标题、缩进和换行规则。

## 3. 依赖方向

```text
小程序 UI ──> 模板 / 核心布局 ──> 独立数据结构
   │                                  ↑
   └──> 云端 API ──> 业务规则 / 存储   │
                       │              │
                       └──> 文件渲染器┘
```

- 布局核心不得依赖 `wx`、CloudBase、Node 文件系统或 Canvas API。
- 渲染器不写业务计费规则；云函数不直接拥有字体换行规则。
- 管理员入口只能展示权限校验后的云端结果；不要通过隐藏 UI 代替云端鉴权。
- 前端使用共享内核做本地预览，云端重新验证生成参数、排版版本组合、字数、页数和额度，并用同版本内核复算；不能信任客户端提交的物理格宽或行列数。
- 预览与生成的版本匹配、发布和失配行为统一遵循下节；后台更换默认预设不应静默改变正在编辑/生成的版式。

### 3.1 共享排版代码与版本匹配（D-032）

**已确认设计，尚待实现与跨端验收。** `packages/paper-core` 的同一套 TypeScript 源码分别编译进小程序和云函数，负责格线、文字占位、换行和分页；Canvas/PDF 适配器仅负责绘制。小程序本地预览不调用云端排版，不因编辑而上传正文；正式生成时云端从可信配置重建输入并复算。

每次预览锁定以下**不可变版本组合**，生成请求和任务沿用该组合。字段名为实施建议，不要求整个小程序与云函数使用相同发布版本号：

| 标识 | 绑定内容 |
|---|---|
| `engineVersion` | 排版算法、文本分段与字体度量算法、布局协议及摘要计算规则 |
| `templateId` + `templateVersion` | 模板及已发布预设，包含固定几何与文字/格线默认样式；`templateVersion` 即预设发布版本，不再设同义版本字段 |
| `fontBundleVersion` | 该预设使用的字体文件、字重、度量数据及已验证回退配置；资源应有内容校验值，不能原址覆盖成另一份字体 |

只接受云端明确支持、经过验证的版本组合；客户端不能任意拼接版本。影响布局或资源内容的变更必须发布新版本，普通 UI 或无关云端业务更新不要求提升排版版本。英数宽度由两端共用的字体度量模块和数据计算，不能分别依赖 Canvas 与 PDF 库的独立测宽来决定换行。字体加载失败不能静默换成系统字体后继续正式预览/导出。

**生成校验：**小程序提交原始内容、已允许的用户选项、锁定版本组合和预览布局摘要。云端先校验请求与资源限制，再按可信版本组合复算并比较摘要；一致后才继续 PDF 生成。摘要覆盖版本组合、分页、格线、文字占位及绘制样式绑定，序列化与数值精度规则须两端一致，具体协议待实现验证。客户端摘要仅用于发现预览差异，不能作为身份、额度、布局合法性或文件权限的依据；无需因此新增正文或摘要的长期存储，日志也不记录包含正文的布局数据。

重复提交先按 [D-037 请求号与参数指纹规则](DATA_AND_CREDITS.md#44-请求号参数指纹与幂等d-037) 识别，同号同参返回原任务，不再次复算或生成。这里的布局摘要用于跨端布局核对，与随任务保存、用于异参检测的参数指纹不同。

**发布与失配：**先部署支持新旧组合的云端实现及资源，再发布包含新版内核的小程序；新预设仅在相应客户端可用且兼容验证通过后启用。更新过渡期保留仍受支持的旧内核、预设和字体资源，正在编辑或生成的内容沿用已锁定组合，不因 active 预设切换而变化；这不产生用户版本选择入口，也不要求为每个版本部署独立云函数。若组合已不受支持、资源不可用或布局摘要不一致，应明确阻止本次导出、保留当前输入，并在版本/资源就绪后重新预览；不能自动按最新版生成，也不扣次数。旧版本的具体支持期限和退出机制仍需实施验证，进行中的生成任务所需资源不得提前移除。

**云端下发边界：**可下发可信预设及版本固定的字体/度量数据；排版执行代码随小程序代码包发布，不通过下载 JS 动态执行实现热更新。微信的[运行限制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/js-support.html)限制 `eval` / `new Function` 动态执行，[分包异步化](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages/async.html)加载的是发布包内代码。网络字体有 [wx.loadFontFace](https://developers.weixin.qq.com/miniprogram/dev/api/ui/font/wx.loadFontFace.html) 支持，但本项目字体授权、加载与 Canvas 真机兼容性仍待验证。微信[更新机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/update-mechanism.html)允许用户继续运行旧版本，因此不能把服务端发布完成视作客户端已同步升级。

### 3.2 不受支持版本的微信更新流程（D-033）

**已确认交互方向，项目接入与真机验收待完成。** 打开小程序时由应用入口统一检查排版兼容性，页面共享结果，不在每个页面的加载/显示事件中重复请求或弹窗；提交生成时仍由云端校验当前请求。仍受支持的旧组合可正常使用，不要求每次客户端与云端发布号不同都更新。

建议在 `App.onLaunch` 只注册一次更新监听，由 `App.onShow` 统一管理业务兼容检查和缓存：冷启动只发起一次检查，返回前台时复用有效结果、合并进行中的请求，并对短时间重复触发节流。各页面只读取应用级状态；手动重试仍经同一入口，具体缓存时长在实施中确定。微信自动检查代码更新与本项目调用云端检查排版兼容性是两个过程，不能把 `hasUpdate` 当成云端兼容结论。业务检查网络失败应提示重试，不直接判定版本不受支持。

1. 云端确认客户端内核不再受支持、需要新版代码时，返回必须更新状态（建议错误码 `UPDATE_REQUIRED`），阻止导出且不扣次。这是业务响应，不是直接推送或执行新代码的指令。
2. 小程序启动时通过 [wx.getUpdateManager](https://developers.weixin.qq.com/miniprogram/dev/api/base/update/wx.getUpdateManager.html) 注册更新监听。微信负责检查并下载已发布的新版代码；`onCheckForUpdate` 的 `hasUpdate` 只说明有新版，只有收到 `onUpdateReady` 才表示下载就绪。
3. 更新就绪后展示“更新并重启”，由用户主动触发 [applyUpdate](https://developers.weixin.qq.com/miniprogram/dev/api/base/update/UpdateManager.applyUpdate.html)；微信重启小程序并应用新版。已有输入时不得直接触发重启，应先提示并让用户保留内容；此决策不授权默认持久化正文，也不能把内存输入视为能够跨重启保留。
4. 没有可用更新、更新未就绪或触发 `onUpdateFailed` 时，保留当前输入并提示稍后重试，继续阻止不兼容导出；不能循环重启，也不能把普通数据重新加载当作代码升级成功。重启后重新校验版本组合并预览，通过后才能生成。

仅预设或字体/度量数据需要刷新、且当前内核支持目标组合时，重新加载可信资源并预览，无须重启小程序。字体加载失败或布局摘要不一致也不应一律归类为客户端需要更新，应按 3.1 节处理实际原因。

发布新版须完成微信审核与发布。管理后台的“最低可用版本”设置可配合旧版本退出，但不能替代云端兼容性校验，也不保证立即覆盖所有用户；具体行为见[微信更新机制](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/update-mechanism.html)。此流程使用微信提供的更新包，不从 CloudBase 下载任意 JS，也不提供下载指定代码版本的接口。

## 4. 初拟代码组织

小程序 UI 按 D-039 使用原生基础组件和少量自定义业务组件，不默认安装整套 UI 库。依赖引入与统一页面设计的边界见 [UI_DESIGN](UI_DESIGN.md)；其具体导航/视觉草案不等同于已经实现的目录。

```text
miniprogram/             微信页面、组件、本地 Canvas 适配
packages/
  paper-core/            纯 TypeScript 文档模型、布局/分页
  paper-templates/       模板定义和默认参数
  contracts/             云端 API 请求响应/状态
renderers/
  canvas/                小程序预览
  pdf/                   服务端 PDF
  # docx/                后续可能增加，首版不实现
cloudfunctions/
  api/                   身份、任务、额度、管理员统计
  render/                受控文件生成
  scheduled/             清理/汇总；确有需要才部署
tests/                   布局基准、兼容性、业务并发测试
docs/                    项目权威文档
AGENTS.md                规则与文档导航
```

这是**代码职责图，不是必须部署多个微服务或函数**。目前仅有 `packages/paper-core` 的部分实现，其余目录为开发规划，不可根据目录图声称云函数、微信端或 PDF 已完成。初期可合并紧密相关的云函数，以真实部署限制为准。

## 5. 信任与隐私边界

微信端发来的 `userId`、role、额度数、订单成功状态和模板成本都不可信。云函数从可信微信调用上下文取得身份，再加载账户及权限；价格与扣费规则只在云端生效。

不默认长期保存正文；不可在日志/统计里记录用户原文。生成文件短期交付，授权用户才能重复领取，过期清理。

## 6. 故障边界

生成与扣次遵循 [D-034 任务状态机](DATA_AND_CREDITS.md#4-可信任务状态机d-034)：先事务预留、事务外生成、事务结算，成功/失败终态不可反转，迟到结果不重新扣次。云端受理的任务按 [D-035 离页体验](PRODUCT.md#41-生成记录与离页体验d-035) 独立于页面生命周期；客户端等待超时、页面关闭或停止查询不等于云端失败。任务恢复限于 [D-036 定义的状态、已有 PDF 和账本处理](DATA_AND_CREDITS.md#43-不保存正文的恢复边界d-036)，不为自动重试保存正文或重新排版。可靠执行交接、记录查询和超时对账必须在 CloudBase 接入时验证，不能依赖小程序留在前台或云函数返回后未被等待的异步代码继续运行。

首版只生成 PDF；模板布局不能为填满纸张而裁切格线或正文，超出可用行数须续页或明确报错。Word 仅保留未来输出适配的架构边界。

## 7. 未来扩展原则

仅为已经存在的工具提取可复用能力。新工具使用独立领域模型、复用账户和额度服务即可；不要为了想象中的未来引入运行时插件加载器、通用工作流或复杂多租户组织结构。
