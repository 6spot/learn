# 架构与产品决策记录

| 编号 | 决策 | 理由 |

| D-016 | 固定版式不能容纳正文时必须续页；超过产品安全限制必须明确拒绝，不能静默丢字 | 保护打印内容完整性 |
| D-017 | 标准纸张规格与默认版式由后台集中配置、提前验证；普通用户默认直接使用 | 减少低频家长用户操作，避免自行调整专业参数 |
| D-018 | 用户只在有特殊需求时展开少量安全的文字/样式设置；不开放自由编辑格宽、行列及边距 | 保持简单、稳定、不会截断的打印体验 |
| D-019 | **每种纸张模板面向用户只提供唯一默认规格**，不设大格版/标准版/小格版选择；由后台更换当前生效版本 | 降低低频用户的选择负担，打开即用 |
| D-020 | 首版四种正式模板固定为 A4 竖版：作文方格 10mm、19×27；田字格和米字格 15mm、12×17；拼音四线三格 4mm 组内线距、6mm 组间距、14组，线长180mm | Owner 确认既有电子试印方案；具体定位、留白见 [规格权威文档](PAPER_PRESETS.md) |
| D-021 | 首版拼音四线三格仅接受用户自行输入的拼音（支持声调），负责书写线上的排版；不提供汉字自动转拼音功能 | 避免多音字与词组读音猜测，降低首版复杂度，保证输入可控 |
| D-022 | 保留用户输入和粘贴的显式换行及空行，不自动合并、拆分段落；自然换行只用于排版，不更改输入 | 避免破坏原文 |
| D-023 | 仅用户主动操作时才整理粘贴文本中的换行 | 默认直接可用，保留用户控制权 |
| D-024 | 输入一次回车代表开始一个新段落，该段按当前文字预设执行首行缩进；连续两次回车额外保留一整行空白；自动折行不新增段落或重复缩进 | 符合用户输入直觉，保持原文与排版的清晰边界 |
| D-025 | 中文句号、逗号等行首禁入点号在方格中平时各占一格；若紧随行末最后一个汉字且已无空格，则与该字共享最后一格（缩小点号并置于格内合适位置）；不设计回退前字换行的第二策略或用户开关 | 保持文字不被截断且避免额外排版分支 |
| D-026 | 方格中英文和数字按实际字体字形宽度分配连续书写空间，不按每字母一格或固定字母数一格；英文单词优先作为整体换行，不提供用户选择的占格模式 | 简单支持中英数混排，避免死板规则浪费格位 |
| D-027 | 英文单词当前行放不下时整体移至下一行；若单词本身长于整行，则仅按完整字符边界安全分行。连续数字及小数点尽量整体排列，保留原文空格；无手动占格/断词模式 | 单一确定性换行规则，不裁字、不修改内容 |
| D-028 | 首版不要求用户选择空白/填字模式：没有可绘制文字时自动输出完整空白纸，有文字时默认正常填字；描红仅由用户主动开启 | 减少操作步骤，默认即能生成 |
| D-029 | 填字与描红共用逻辑文本布局、占位、换行和分页；描红可使用专用字体，但必须在同一已分配格位/行带内绘制，不独立重新分页。字号、描红灰度采用后台验证的默认预设，首版无用户调节入口 | 复用统一排版，同时允许适合练字的参考字形 |
| D-030 | 首版字体必须具有明确的**免费商业使用授权**，并适用于所采用的 PDF 交付及必要的嵌入方式；字体由产品预设决定，用户不选择字体 | 避免授权成本和复杂交互；确保 PDF 可稳定打印 |

| D-032 | 小程序与云端共用同一套纯 TS 排版源码，采用本地预览、云端复算；一次预览和生成锁定相同的排版内核、预设及字体/度量资源版本，复算布局一致才导出。代码随小程序发布，云端下发可信配置及资源；不兼容时明确要求更新/重新预览，不静默改用新版 | 仅预设版本相同不足以保证分页一致；兼顾即时预览与云端可信生成。匹配的是排版版本组合，不要求整个小程序与云函数的发布版本号相同；详细规则见 [ARCHITECTURE](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032) |

## 开发推进与验收分工

**D-044（2026-10-10，Owner 授权）**：按现有任务顺序自主完成首版功能、模拟与本地集成验证；实现中的具体工程取舍由开发代理决定，无须逐项授权。已安装的微信开发者工具可直接用于工程编译和模拟器验证。真实账号、CloudBase/字体资源等服务组件配置、真机与实体打印统一留至最后，由 Owner 按 T24 的交付清单完成。阶段完成后提交、归档并推送远程。

开发任务的收尾必须列明完成的代码和本轮验证，并将外部环境验收逐项移交 T24；移交不等于验收通过。涉及正式 active 预设、字体许可和上线资质的发布门槛保持有效。只完成部分代码的任务不归档；T24 在最终外部验收前保持未完成。具体操作与证据集中在 [最终配置与验收清单](FINAL_ACCEPTANCE.md)。

**D-045（2026-10-10，按 D-044 自主确定的开发配置边界）**：免费额度、文件/记录/指纹保留期、请求有效窗口、任务期限和资源限制使用受控服务端配置；本地模拟可用明确标注的测试值，生产启动要求显式提供并校验配置，不把测试值作为未披露的生产默认。保留与过期机制必须在开发阶段完整实现；生产数值和告知一致性由最后的组件配置验收收齐。

**D-046（2026-10-10，按 D-044 自主确定，关闭 O-014 的实现取舍）**：主动整理换行采用保守规则，只合并连续非空行之间、上一行不以句末/段末标点结束且下一行不是列表或缩进行首的单个换行；空行、列表边界、段落末尾换行和现有空白均保留。合并拉丁/拼音词边界时补一个必要空格，汉字连续处直接连接。必须先显示真实输入的修改前后对照；取消不改变输入，应用只替换正文。一次撤销精确保留整理前正文，继续编辑正文即清除旧撤销，避免覆盖新输入；修改标题/描红/设置不清除正文撤销。弹窗期间正文已变则拒绝应用过时预览。规范与样例由 [UI_DESIGN](UI_DESIGN.md) 维护，原文默认保留规则不变。
