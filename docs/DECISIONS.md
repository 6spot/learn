# 架构与产品决策记录

> 状态：持续维护。明确区分“已确认”“待验证”“尚未决定”；这份文档是讨论后落地更新的入口。

## 已确认

| 编号 | 决策 | 理由 |
|---|---|---|
| D-001 | 面向中国大陆家长、学生、老师的微信原生小程序；个人开发者主体起步 | 低频使用、微信自然传播 |
| D-002 | 产品正式名称暂不确定；仓库 `learn` 为代号 | 避免为了命名耽误核心设计 |
| D-003 | 学习纸张是首个工具；通用账户/权益/统计与纸张工具分层 | 后续可增加其他学习工具 |
| D-004 | 使用微信关联的 CloudBase 云开发环境；不自建服务器、不使用 EdgeOne | 简化维护和小程序云调用 |
| D-005 | 当前不加入 AI、OCR | 不属于核心打印纸张体验 |
| D-006 | 模板定义、内容、物理布局和渲染适配器分离 | 便于同源预览和多格式导出 |
| D-007 | **首版正式导出仅支持 PDF**；DOCX 推迟到有真实编辑需求后的兼容性阶段 | 家长主要下载打印，先保证可靠版式 |
| D-008 | 同一小程序设管理员入口，复杂管理交给 CloudBase 官方控制台 | 不重复开发独立后台 |
| D-009 | 微信无感身份、少量必要用户数据；不默认保存作文正文 | 降低注册门槛和隐私风险 |
| D-010 | 商业方向为免费次数、可选广告奖励、购买次数包，不走强制订阅 | 低频、低价场景 |
| D-011 | 成功生成任务才扣一次；预览、重复下载不重复扣 | 用户友好、账目清晰 |
| D-012 | 不提前建设通用插件框架、大型运营 CMS 或复杂微服务 | 先完成可用产品 |
| D-013 | 标题、对齐、首行缩进、自然换行及段落为跨模板通用文字排版能力；模板只提供默认组合 | 田字格、米字格与作文格可复用相同排版功能 |
| D-014 | 所有纸张在完整的预设书写区域铺格，不提供是否铺满开关 | 空白区始终保留格线，安全边缘允许留白 |
| D-015 | 提供经预先计算与打印验证的固定纸张规格/版式，完整单元优先，边缘宁留白不裁切 | 避免残格、越界和打印内容被截断 |
| D-016 | 固定版式不能容纳正文时必须续页；超过产品安全限制必须明确拒绝，不能静默丢字 | 保护打印内容完整性 |
| D-017 | 标准纸张规格与默认版式由后台集中配置、提前验证；普通用户默认直接使用 | 减少低频家长用户操作，避免自行调整专业参数 |
| D-018 | 用户只在有特殊需求时展开少量安全的文字/样式设置；不开放自由编辑格宽、行列及边距 | 保持简单、稳定、不会截断的打印体验 |
| D-019 | **每种纸张模板面向用户只提供唯一默认规格**，不设大格版/标准版/小格版选择；由后台更换当前生效版本 | 降低低频用户的选择负担，打开即用 |
| D-020 | 首版四种正式模板固定为 A4 竖版：作文方格 10mm、19×27；田字格和米字格 15mm、12×17；拼音四线三格 4mm 组内线距、6mm 组间距、14组，线长180mm | Owner 确认既有电子试印方案；具体定位、留白见 [规格权威文档](PAPER_PRESETS.md) |
| D-021 | 首版拼音四线三格仅接受用户自行输入的拼音（支持声调），负责书写线上的排版；不提供汉字自动转拼音功能 | 避免多音字与词组读音猜测，降低首版复杂度，保证输入可控 |
| D-022 | 保留用户输入和粘贴的显式换行及空行，不自动合并、拆分段落；自然换行只用于排版，不更改输入 | 避免破坏原文 |
| D-023 | 仅用户主动操作时才整理粘贴文本中的换行 | 默认直接可用，保留用户控制权 |
| D-024 | 输入一次回车代表开始一个新段落，该段按当前文字预设执行首行缩进；连续两次回车额外保留一整行空白；自动折行不新增段落或重复缩进 | 符合用户输入直觉，保持原文与排版的清晰边界 |
| D-025 | 中文句号、逗号等行首禁入点号在方格中平时各占一格；若紧随行末最后一个汉字且已无空格，则与该字共享最后一格（缩小点号并置于格内合适位置）；不设计回退前字换行的第二策略或用户开关 | 保持文字不被截断且避免额外排版分支 |
| D-026 | 方格中英文和数字按实际字体字形宽度分配连续书写空间，不按每字母一格或固定字母数一格；英文单词优先作为整体换行，不提供用户选择的占格模式 | 简单支持中英数混排，避免死板规则浪费格位 |
| D-027 | 英文单词当前行放不下时整体移至下一行；若单词本身长于整行，则仅按完整字符边界安全分行。连续数字及小数点尽量整体排列，保留原文空格；无手动占格/断词模式 | 单一确定性换行规则，不裁字、不修改内容 |
| D-028 | 首版不要求用户选择空白/填字模式：没有可绘制文字时自动输出完整空白纸，有文字时默认正常填字；描红仅由用户主动开启 | 减少操作步骤，默认即能生成 |
| D-029 | 填字与描红共用文本布局、定位与分页；描红仅改变参考文字的绘制样式。字号、描红灰度采用预设并在后台验证，首版不提供用户调节入口 | 避免重复实现和无效配置，保证打印一致性 |
| D-030 | 首版字体必须具有明确的**免费商业使用授权**，并适用于所采用的 PDF 交付及必要的嵌入方式；字体由产品预设决定，用户不选择字体 | 避免授权成本和复杂交互；确保 PDF 可稳定打印 |

## 已排除的当前方案

- Cloudflare Workers、EdgeOne 或 Oracle VPS 作为初期必需后端。
- HTML 截图插进 Word 并宣称“可编辑 DOCX”。
- 把纸张引擎写死在某个微信页面或云函数内。
- 通过客户端字段决定账户、管理权限和扣次。
- 提前建设 AI 作文批改、OCR、强制手机号、会员订阅和通用工具插件平台。

## 变更流程

每次讨论达成结论：说明新决定、取舍原因、影响的文档及验证条件；将对应 O 项关闭或转为 D 项，再更新对应详细文档。**不要把待验证猜测写成已确认规则**。
