## 2. 可以视为已确认的开发输入

- 微信原生小程序 + 关联 CloudBase，首版只交付 PDF，其他技术栈及高级业务不随意增加。
- 四种纸张均为固定 A4 竖版，每模板只有一个当前发布规格；无用户格宽、边距、格数选择。几何数值按 [D-038 中心线定义](PAPER_PRESETS.md#21-中心线墨迹与打印安全区域d-038) 计量，完整墨迹与打印安全边界另行验收。
- 无字直接生成完整空白纸、有字默认填字、描红主动开启；无字号/灰度/字体选择器。
- 标题、段落、缩进、标点、英文数字、跨页及原文保留按已确认 D 项；两端按 [D-032](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032) 共用排版源码、匹配版本并核对布局，Canvas/PDF 渲染器**不能自行决定分页**。
- 默认字体按 [D-031 分配表](PAPER_ENGINE.md#首版字体分配与描红d-031) 使用，注意作文方格描红沿用 MiSans，霞鹜文楷 GB 中文描红仅用于田字格、米字格；已从官方取得三种 Regular 开发候选，路径、版本及来源见 [字体资源](../assets/fonts/README.md)。具体嵌入/分发许可、字形及打印仍待验证。
- 模板**格线算法由代码定义**；固定尺寸和默认样式以 CloudBase 中可信的已发布不可变版本为准，预览与云端导出锁定相同版本。不建大型 CMS。
- 用户身份、额度、成功扣次、任务和文件权限由可信云端验证；不默认持久保存作文正文。[D-036](DATA_AND_CREDITS.md#43-不保存正文的恢复边界d-036) 已确认恢复仅处理状态、已有 PDF 和账本，不保存正文供自动重试；失败后用户需要时重新粘贴生成。
- 打开小程序时由应用入口统一检查版本，页面共享结果；受理后的生成任务独立于页面运行，通过“我的 → 生成记录”查看结果。遵循 [D-033 更新流程](ARCHITECTURE.md#32-不受支持版本的微信更新流程d-033)、[D-034 结算规则](DATA_AND_CREDITS.md#4-可信任务状态机d-034) 及 [D-035 记录体验](PRODUCT.md#41-生成记录与离页体验d-035)，这些设计已确认，接入仍待实现。

## 3. 当前真实进度与优先顺序

仓库现有 `packages/paper-core` 的几何、基础方格文字占位/分页代码与 Node 测试。**不要将这些当作可运行的小程序或 PDF 服务**，也不要用此前采用占位字体的试验 PDF 证明真实字体已验收。接手先运行 `cd packages/paper-core && npm install && npm test`，再检查尚未覆盖的字形边界；历史测试结果不能替代本机/CI 验证。

按 [ROADMAP](ROADMAP.md) 及 [Trellis 任务总表](../.trellis/tasks/10-10-learn-v1/task-map.md) 的阶段入口继续。T25 当前稿已按 D-043 接受，页面开发前读取 [UI_DESIGN](UI_DESIGN.md)，不再等待样式精修。先由 T01 提供最小原生宿主和两端构建，T08/T09 可利用现有几何提前产出真实空白预览/PDF，再按以下能力逐步集成：

1. 稳定纯 TS 排版：补足复杂标点、实际字宽、跨页极端样例与微信运行环境兼容；拼音四线三格另按行带开发，不复用汉字方格坐标算法。
2. Canvas 预览 + PDF 渲染共用同一版布局数据；校验 A4 真实尺寸、中文字体与多页结果，不允许裁字。
3. 原生小程序最小流程：模板 → 可选文字/描红 → 预览 → 生成 PDF/下载。
4. 接通关联 CloudBase：已发布预设版本、可信生成/幂等/次数、离页任务受理与结果查询、访问权限及短期文件交付。
5. 按 [TESTING](TESTING.md) 完成端到端、隐私、黑白实体打印与不同设备验收。
