## 2. 可以视为已确认的开发输入

- 微信原生小程序 + 关联 CloudBase，首版只交付 PDF，其他技术栈及高级业务不随意增加。
- 四种纸张均为固定 A4 竖版，每模板只有一个当前发布规格；无用户格宽、边距、格数选择。
- 无字直接生成完整空白纸、有字默认填字、描红主动开启；无字号/灰度/字体选择器。
- 标题、段落、缩进、标点、英文数字、跨页及原文保留按已确认 D 项；Canvas 和云端 PDF **不能各自计算分页**。
- 字体默认方案为 MiSans 正常填字、霞鹜文楷 GB 中文描红、MiSans Latin 拼音；用户将在开发阶段提供字体文件，使用前需完成许可证及字形/打印验证。
- 模板**格线算法由代码定义**；固定尺寸和默认样式以 CloudBase 中可信的已发布不可变版本为准，预览与云端导出锁定相同版本。不建大型 CMS。
- 用户身份、额度、成功扣次、任务和文件权限由可信云端验证；不默认持久保存作文正文。

## 3. 当前真实进度与优先顺序

仓库现有 `packages/paper-core` 的几何、基础方格文字占位/分页代码与 Node 测试。**不要将这些当作可运行的小程序或 PDF 服务**，也不要用此前采用占位字体的试验 PDF 证明真实字体已验收。接手先运行 `cd packages/paper-core && npm install && npm test`，再检查尚未覆盖的字形边界；历史测试结果不能替代本机/CI 验证。

按 [ROADMAP](ROADMAP.md) 继续：

1. 稳定纯 TS 排版：补足复杂标点、实际字宽、跨页极端样例与微信运行环境兼容；拼音四线三格另按行带开发，不复用汉字方格坐标算法。
2. Canvas 预览 + PDF 渲染共用同一版布局数据；校验 A4 真实尺寸、中文字体与多页结果，不允许裁字。
3. 原生小程序最小流程：模板 → 可选文字/描红 → 预览 → 生成 PDF/下载。
4. 接通关联 CloudBase：已发布预设版本、可信生成/幂等/次数、访问权限及短期文件交付。
5. 按 [TESTING](TESTING.md) 完成端到端、隐私、黑白实体打印与不同设备验收。

## 4. 尚未冻结但**不阻塞开始开发**的事项

- 真正字体文件、字重/字号、描红灰度、拼音基线、缺字策略及 MiSans PDF 子集嵌入许可解释：需要样张与具体部署验证，**上线前必须通过**。
- 家庭打印机安全边界/线宽灰度实测、CloudBase 环境配额和模板发布最小接口：实施阶段完成。
- 第一版具体少量进阶设置、「整理换行」转换规则：**不要未经确认擅自添加复杂设置或静默改写输入**。
- 个人主体支付/激励广告可用性、次数包价格、广告奖励数值，以及后续 DOCX/其他工具：保留未来边界，不是先做纸张 PDF 闭环的前置条件。

当现有文档互相冲突时，以 [DECISIONS](DECISIONS.md) 的已确认决策与 [PAPER_PRESETS](PAPER_PRESETS.md) 的物理规格为准；暂停做会改变产品体验的新取舍，提交决策说明让 Owner 确认。**可独立验证的工程细节不必逐项请求 Owner 同意。**
