# 首版 UI、页面与导航设计

> 2026-10-10。D-039 组件策略、D-040 进阶范围、D-041 冷白方向、D-042 同页编辑与层级改进已确认。D-043 将当前稿接受为功能开发的界面基线，O-015 本轮看稿关闭；后续可以调整样式细节，旧暖色稿不作为实现基线。
>
> 当前开发基线：[冷白八页面候选](ui/native-preview.html)。已覆盖建议的八个页面，以及记录详情五种状态、记录列表的空/失败状态；可从稿件侧栏直达。 [旧完整稿](ui/preview.html) 仅保留作已否定方案的参考。HTML 仅用于界面与交互评审，不是小程序实现，不能验证真实排版、微信 API 或云端任务。

> **同页编辑精修候选**：首页保留四象限并提高模板辨识度；编辑页顶部为较浅的局部格线，下面按文字、描红、折叠进阶设置的顺序组织。“查看整页”与文字区标题同行，正文始终可见，避免标签切换。Owner 已同意此方向，并要求控制默认显示内容与层级；当前画面已按 D-043 接受为开发基线，后续按实际使用迭代。

## 1. 已确认：组件与变更边界（D-039）

- 使用微信原生小程序 WXML / WXSS / TypeScript。按钮、输入、文本域、开关、滚动、Canvas 等交互优先使用微信原生基础组件，保留键盘、焦点、禁用和加载语义。
- 官方 WeUI 是可选的样式/组件方案，不等同于运行时基础组件。首版不默认安装整套 WeUI、Vant、TDesign，也不逐页自行选择不同组件库。
- 模板条目、纸张预览、额度摘要、生成记录条目、状态展示等项目业务 UI 按实际复用需求封装；业务组件不等于可见卡片，不重造基础输入控件，不预建通用 UI 框架。
- 新增复杂通用控件时，先说明场景、原生能力缺口、维护/体积/兼容成本和按需引入方式，在对应任务统一评审，不能以写页面为由随意添加依赖。
- 页面、菜单入口、布局和视觉规范按当前确认基线实现。实现采用共享样式值与组件，不能各页面自行添加颜色、字号、圆角、菜单、营销模块或动效风格。
- 产品取舍先记录 DECISIONS，再更新本文；纯实现细节遵循已确认规范并自行验证。具体工程检查见 [前端组件规范](../.trellis/spec/frontend/component-guidelines.md)。

## 2. 首版信息架构基线

底部使用原生 tabBar，只有 **纸张 / 我的** 两个一级入口。其余页面使用原生导航栏与返回路径；编辑、预览、记录详情不显示底部 tabBar，聚焦当前操作。首版没有商城、发现、社区或单独的“生成”标签。

```text
纸张（默认首页）
  └─ 选择模板 → 编辑纸张
                  ├─ 查看大图 → 分页预览
                  └─ 生成 PDF ──────────┐
                        分页预览 → 生成 PDF ┤
                                         ▼
我的                                  生成记录详情
  ├─ 生成记录 → 记录列表 ────────────────┘
  ├─ 使用反馈 → 微信反馈能力（真机待验证）
  ├─ 隐私与数据
  └─ 运营中心（仅管理员）
```

新生成已确认受理后进入同一“生成记录详情”，不再建立另一套独立结果页。尚未确认受理时停留原页显示查询状态，不假报生成中。响应丢失按原请求查询。

## 3. 页面清单与菜单归属

| P04 | 我的 `pages/me/index` | 底部“我的” | 额度摘要、记录、反馈、隐私、管理员入口 |

## 4. 逐页布局

### P01 纸张

从上到下：原生导航栏 → 小标题“选一种纸张”和一句提示 → 2×2 四象限模板区 → “A4 竖版 · 导出 PDF”说明 → 底部 tabBar。模板从左上到右下依次为作文方格、田字格、米字格、拼音四线三格。针对 Owner 指出首页缺少内容背景，本轮将整个首页内容区明确设为白底，纸张继续使用轻边界辨识；不为每个象限新增卡片。

每象限直接显示一张有存在感的 A4 缩略纸，下方模板名及一行用途，整个象限可点击；标准宽度下纸张约 `220–236rpx`，小屏自适应。四种纸张用留白和统一对齐组织，同屏容易比较；不使用大十字表格线，也不加外卡＋内底板＋纸张三层包裹。缩略图提高屏幕格线辨识度，其绘制样式只用于 UI 示意，不定义正式打印线宽。不重复添加“选择规格”或“立即生成”按钮，不加搜索、分类标签、轮播广告、最近使用模块或占位未来工具。

### P02 编辑纸张

原生导航栏展示模板名。顶部白纸格线片段直接接在导航下，无独立灰底的“局部预览 · A4”说明栏；下方白色编辑区按 D-042 合为一页，不再设置文字/排版标签。“文字内容”区标题右侧放“查看整页”，整个格线片段也可点击进入 P03。正文之后依次为描红行、默认折叠的进阶设置。底部保持唯一主操作“生成 PDF”。合并方向已确认，具体画面按 D-043 当前稿推进，真机布局另行验证。

| 区块 | 视觉层级 | 内容 |
|---|---|---|
| 纸张预览 | 全宽、较矮的白底格线片段，无纸张外轮廓或投影；屏幕线色采用中性灰并弱于正文 | 当前模板局部与文字/描红示意，点击查看完整纸张 |
| 文字内容 | 唯一主要编辑区；区标题、字段名与辅助说明分级，正文保留稳定高度 | 可选标题、正文、整理换行及撤销 |
| 描红 | 正文之后的独立紧凑行；与文字区通过留白和细分隔区分，开关直接可见 | 一句用途说明与开关，不增加模式选择或调节项 |
| 进阶设置 | 低于正文与描红的次级入口；默认只显示名称、当前摘要和展开提示 | 展开才显示标题对齐、首行缩进与恢复默认；不能合并后自动展开 |

区块内不再为每个字段、开关加一张内容卡。文字区与设置区使用一致的左右对齐、适量段间距和细分隔，不能仅移除标签后把所有控件平铺。字段标签只保留“标题”“正文”（拼音模板为“拼音”），不在后面加“选填”；在文字区统一说明“不填文字即可生成空白纸”。标题仍可容纳长内容，正文多行输入；不得因控件默认最大长度静默丢字。正文约 200～230px 的设计稿可视高度为起点，窄屏允许页面纵向滚动，不为把所有设置塞入首屏而压缩正文。

- 顶部从当前模板的同一格线/文字图形裁取局部，不把整张 A4 压扁、不重复平铺整页图片，不改变纸张几何或正式分页。片段底边避开半行文字，完整纸张及四边留白在 P03 查看；局部画面不冒充最终打印全貌。离线稿的格内文字只展示界面反馈，正式落格与换页仍由共享排版数据决定。
- 局部预览不放格宽、行列、边距、版本号等工程参数；正文填入后可看到文字/描红反馈。拼音输入提示直接输入拼音，不做自动转拼音。
- 预览下方不单独展示“空白纸”或填字状态摘要，也不为其预留空行；格线直接衔接操作区。留空说明只在文字输入区出现，排版摘要留在排版设置中，输入前后预览高度保持一致。
- 描红在正文后的独立行直接可用，不依赖切换标签或打开进阶设置：无文字时仍输出空白，不出现“空白/填字”模式切换。切换描红或展开设置不重建正文控件、不丢焦点与输入。
- 底部保留“生成 PDF”与“成功生成才扣次”，不再重复可留空的提示。顶部局部可点击看完整预览，无须强制走 P03 才能生成。
- D-040 已确认进阶设置包含“标题对齐、正文首行缩进”，跨模板复用、默认收起。折叠摘要显示当前选择，提供恢复默认入口；恢复只影响这两项，不清空文字。候选控件为原生单选：标题左对齐/居中/右对齐，缩进按模板默认/不缩进，当前取值与展示按 D-043 基线，实际默认值由共享预设确定。
- “整理换行”紧邻正文标签，空正文时不可用；主动点击后展示整理前/后的对照，取消保持原文，明确应用后才改变正文，并提供撤销入口。标题、描红及进阶设置不受整理影响。转换与撤销按 D-046，默认绝不自动整理输入。
- D-046 的转换只合并连续非空行间的单换行：前行以 `。！？.!?；;：:`（后可跟闭引号/括号）结束、后行具有列表前缀或行首缩进时保留边界。保留全部空行及已有空白；中英文边界根据实际字符连接，拉丁/拼音词间必要时插入一个空格。例：`春天来了\n小草发芽。` → `春天来了小草发芽。`；`hello\nworld` → `hello world`；`第一段。\n第二段`、`第一段\n\n第二段`、列表和缩进均不变。
- 应用前再次比较预览快照与当前正文，避免覆盖弹窗期间的新编辑。撤销只恢复上一次整理前的完整正文；继续编辑正文清除旧撤销，标题/描红/设置变化则保留。无改动时不允许应用，取消不改文。离线 HTML 仍只演示固定样例，真实转换由 T18 实现并测试任意输入。
- 正式实现时，两项设置进入共享排版输入和云端允许值校验，并参与生成参数指纹；不得通过客户端设置覆盖可信几何、字体或字号预设。
- 键盘弹起时保证输入可见；顶部预览随编辑页面滚出视野，不吸顶占据正文空间。操作区不遮挡输入，优先随内容流动或按键盘状态调整，真机决定实现细节。离线稿可检查缩短视口与焦点滚动，但不能据此宣称微信键盘和安全区已验收。

### P03 分页预览

原生导航栏“纸张预览” → 浅冷灰阅读背景内直接放一张 A4 白纸 → 页码与上一页/下一页 → 主按钮“生成 PDF”。只有阅读背景和纸张本身，纸张可有极轻的边缘阴影；不再包裹卡片或底板。单页隐藏多余翻页按钮，多页边界有禁用态。

支持在同一个预览页内查看与缩放，不改变导出物理尺寸。点击纸张或明确的“放大”入口只调整当前纸张视图，并提供“还原”；不再弹出第二个同名“纸张预览”窗口。放大后的内容在阅读区域内滚动查看，页码与生成入口仍属于当前页面；返回一次直接回编辑页，保留输入和设置。大页数不一次绘制所有大画布；空白、填字和描红使用同版布局。预览字体/资源失败给出重试，不能展示系统字体替代的正式预览。

### P04 我的

原生导航栏“我的” → 白底额度区（“可用生成次数”，从云端读取）→ 白底菜单组 → 底部 tabBar。针对 Owner 指出的裸露浅灰底缺少承托，额度、常用菜单、管理员菜单按完整分组提供白色内容背景，浅冷灰只用于组间留白和页面余下区域；白底横向铺开，不增加带阴影的圆角卡或逐行卡片，菜单组内部仍用细线分行。具体画面按 D-043 当前稿推进。

菜单顺序为“生成记录”“使用反馈”“隐私与数据”；管理员在独立分组看到“运营中心”。不要求头像、昵称、手机号或注册，不显示未启用的购买/广告入口。额度下说明“预览不扣次，成功生成才扣次”，不编造生产免费次数。

### P05 生成记录

原生导航栏“生成记录” → 按提交时间倒序的分隔行列表。每条展示模板名、时间、文本状态及成功后的页数/有效期摘要；状态直接用文字表达，不堆叠徽章或卡片。不展示输入标题或正文缩略图。首版无必要不添加筛选/搜索。

空列表显示“还没有生成记录”和“去选纸张”；请求失败在原区域显示重试，不覆盖已有有效列表。进入/返回页面刷新，可见且有未结束任务时适度刷新；离页停止轮询。

### P06 生成记录详情（复用结果页）

原生导航栏“生成记录” → 结果状态与当前主操作 → 文件信息 → 次级导航。成功有效时，“打开 PDF”紧跟成功说明，“保存/分享”为次级操作；“查看生成记录”用轻量链接放在文件信息之后。其余状态只展示适用操作，不能因上次成功而在查询失败时呈现可直接领取的按钮。状态图标与标题为主视觉；文件信息带区块标题，元数据采用次级标签。用背景或间距分开完整区块，不为每个元数据字段再加卡。核心状态以云端为准：

| 状态 | 内容与主操作 |
|---|---|
| 等待处理/生成中 | 文本说明“可以离开，稍后在生成记录查看”；不展示虚假百分比；可查看记录列表 |
| 成功且文件有效 | “PDF 已生成”；主按钮“打开 PDF”，次入口“保存/分享”；交付期内重复领取不扣次 |
| 失败 | 可理解原因及未消费/已释放说明；有原编辑内容则返回编辑，否则“去选纸张”重新粘贴；不从历史恢复原文 |
| 成功但文件过期 | “文件已过期”；说明原任务已成功，不能继续领取；不自动重做或扣次 |
| 查询失败/断网 | 保留最后已知状态，明确当前查询失败并可重试；不擅自变为任务失败 |

打开、保存和分享均从鉴权领取成功文件开始，具体微信接口待 T21 真机验收。模板分享与用户主动分享 PDF 分开，不能默认附带私人内容。

### P07 隐私与数据

原生导航栏 → 易读的“我们处理哪些数据 / 为什么需要 / 保存与删除 / 联系与反馈”分节说明 → 数据删除入口。文本与真实云端行为保持一致；删除的范围、账本保留及确认交互随 O-007 定稿，不写虚假的即时彻底删除承诺。

### P08 运营中心

原生导航栏 → 日期口径说明 → 新增用户、成功生成、失败率、额度消耗等双列文字指标 → 模板使用列表。指标用对齐和横线区分，无独立卡片底色。数字为云端聚合结果，O-009 未确认的指标不先虚构口径；不展示文章、用户私人标题或可直接改余额的自由输入框。管理员隐藏入口和服务端鉴权同时具备。

## 5. 当前视觉样式基线

方向：**真实白纸、冷白界面、清楚的工具层级**。纸张本身为纯白，周围浅冷灰形成边界；文字采用深灰黑，强调色少量使用。页面不做泛黄、棕色或旧纸质感，也不把纯白纸张染蓝。

首页四象限、详情清楚分区继续保留；不靠重复套卡分组，不用取消全部层级来减少容器。首页缩略图保留完整白纸比例，通过主格线与辅助线的显示对比区分模板；编辑局部预览减弱格线干扰，文字保持可读。这些屏幕调整不改正式预设。

| 颜色角色 | 当前方向 / 后续可调整 |
|---|---|
| 纸张 | `#FFFFFF`，贴近真实白纸 |
| 页面与预览背景 | 接近白色的浅冷灰，如 `#F5F6F8`；与白纸形成轻微区分，不做明显蓝底 |
| 主要文字 | 深灰黑，如 `#202329` |
| 辅助文字 / 分隔 | 保持可读对比，用于次要信息和必要分组；具体值参考当前稿，后续可调整 |
| 强调色 | 少量使用，当前稿使用少量蓝色，不沿用朱砂/棕色方案 |
| 字体 | 先使用符合小程序阅读习惯的系统字体；旧稿宋体方案未获认可，不视为已确定 |

纸张显示为白色是屏幕视觉约束，不更改 PAPER_PRESETS 的物理几何、PAPER_ENGINE 的字体分配或 PDF 渲染契约。缩略图与真实预览仍分别验证，颜色修订不代表版式/真机验收。


当前稿以正文输入 16px、字段名 14px、辅助说明 12px 左右作为可读性起点；与文字区标题同行的“查看整页”使用至少约 14px 文案和 44px 点击高度。主按钮、开关和折叠入口保留足够触控区域。数值属屏幕界面基线，不对应纸张字号，也不直接把 px 当作正式 rpx。

`rpx` 不是固定物理尺寸；小屏、大字号及系统缩放下必须实测。按钮/标签允许合理换行，不靠缩小字号塞进固定高度。安全区、微信胶囊与键盘不使用硬编码屏幕坐标。

本轮应用 `emil-design-eng` 与 `apple-design` 的信息分组、渐进展开、按下反馈和焦点原则：默认路径保持简短，特殊文字设置可发现，取消/撤销有明确退路。HTML 对照面板支持焦点约束、Escape 关闭与返回触发按钮；微信实现使用平台能力验证等效行为，不引入 Web 动画框架。历史讨论提炼见 [设计参考](../.trellis/tasks/archive/2026-10/10-10-v1-ui-design/research/history-reference.md)。

## 6. 共用业务组件与状态

建议的职责包括模板条目、纸张预览、额度摘要、记录条目、状态展示、菜单行和页面操作区。组件复用不要求显示外框；必要的区块背景用于表达职责。首次实现先用最少结构，出现真实复用再抽取；组件名称及路径由实现任务确定，不提前建设组件框架。

所有异步区域至少说明加载、空数据、成功、失败/重试；会重复触发的按钮具有 loading/disabled 行为。禁用必须有可理解原因，如资源未就绪、输入超过安全限制、余额不足；不把“更新失败”泛化为所有错误。

## 7. 页面一致性与权限验收

- 页面清单、原生 tabBar/返回路径、主次按钮与本稿确认版一致；新增入口先更新设计。
- 检查首页为四象限；纸张编辑的预览/文字/排版三个区块、记录详情的状态/信息/操作层次能清楚区分。允许必要的分组背景，同时避免重复内容卡和多余纸张外壳，不能只改圆角或去掉全部背景来应付层级问题。
- 按 D-042 检查同页顺序与层级：正文为主，描红直接可见，进阶默认折叠；默认画面不得出现已折叠的单选项或恢复按钮。展开/收起与预览返回保留文字、描红、进阶选项和摘要。检查较大字号、小屏和缩短视口下的纵向可达性，不能靠压缩正文或新增内层滚动来塞下控件。
- 键盘、大字号、小屏和底部安全区不遮挡文本/操作；输入保持可见和可编辑。
- 编辑、预览、我的、记录共享应用兼容状态；不逐页检查版本或注册更新监听。
- 切换/返回保留尚在内存中的编辑内容，不宣称跨重启恢复；从记录进入不伪造历史草稿。
- 进阶设置默认收起、摘要准确、恢复默认不清空输入；整理必须主动预览并应用，可撤销，取消不改文；不得把固定样例演示当作生产转换算法。
- 普通用户无法访问管理员 API，记录与文件逐次鉴权；UI 隐藏不能代替权限。
- 屏幕预览稿与微信真机、正式字体和实体打印的验证证据分别记录。
