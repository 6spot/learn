# 用户数据、生成任务与次数权益

> 状态：逻辑模型草案。字段名和索引需根据实际数据库事务与使用量确认。本文不设定定价。

## 1. 身份和权限

微信小程序无感识别用户；CloudBase 云函数从可信调用上下文获取 OpenID，再关联内部 `userId`。不强制昵称/头像/手机号，也不把微信 OpenID 视作已获知真实身份。

云端维护唯一 Owner 管理员名单，服务端接口逐次鉴权。小程序隐藏管理员页面只是界面逻辑，不是安全边界。

## 2. 最小数据集合

| 集合 | 核心作用 | 约束 |
|---|---|---|
| `users` | 内部用户 ID、OpenID 关联、创建/最近活跃、状态 | 最小个人信息 |
| `credit_accounts` | 免费/广告/购买额度余额快照 | 只由云函数写入 |
| `credit_ledger` | 赠送、预留、消费、返还和人工调整不可变流水 | 用于审计与对账 |
| `generation_jobs` | 云端任务号、前端请求号、所属用户、参数指纹及其校验版本（见下文 D-037）、锁定的排版版本组合（见 [ARCHITECTURE](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032)）、状态、创建/结束时间、执行批次与超时依据、额度预留关联、页数、产物路径及文件失效时间、安全错误类别 | 默认不保存正文；支撑本人生成记录查询，记录/幂等保留期与文件有效期分别定义 |
| `daily_stats` | 按日期和工具/模板汇总的指标 | 不存私人内容 |
| `app_config` | 免费额度与可控业务参数 | 仅可信后台修改 |
| `admin_audit_logs` | 管理员的额度、配置等敏感操作 | 必须可追溯 |

当正式接入支付/广告时，再加 `orders`、`reward_records` 等集合。**纸张格线类型与排版算法属于代码；固定纸张规格及默认样式属于 CloudBase 后台维护的已发布模板版本**，每个模板只存在一个当前生效版本。预览和 PDF 均绑定同一不可变已发布版本，服务端不接受用户自报的行列或边距覆盖。初期可由 CloudBase 控制台维护预设数据，不开发通用模板 CMS；字段、集合拆分及发布操作细节在实施中验证。参见 [CLOUDBASE](CLOUDBASE.md)、[PAPER_ENGINE](PAPER_ENGINE.md)。

用户和额度服务中的生成记录保留 `toolId`/`usageType` 维度，以支持未来其他学习工具，但不预建复杂的跨工具计费系统。

## 3. 次数包规则（当前共识）

- 免费用户每月可获得一定生成额度，具体数值待定。
- 完成可验证的激励广告可以获得额外生成次数，启用条件和具体数值待定。
- 可以购买一次性的生成次数包；低频使用，不强制月度订阅。
- 购买次数原则上不因月度免费额度重置而清零，最终有效期和退款规则以后决定。
- **优先消耗免费额度**，购买额度最后使用；广告额度和免费额度之间的优先级待讨论。
- 编辑与预览不限计次；一次**成功生成 PDF 任务**计一次；后续新格式的计次规则再讨论。
- 同一份已生成文件在可领取期限内重复下载不重复扣次数。

不做充值货币钱包；用户购买的是明确数量的生成权益，不是储值资金。

## 4. 可信任务状态机（D-034）

**体验与结算规则已确认，CloudBase 实现及并发验证待完成。** 云端受理的任务独立于页面运行，记录与离页体验以 [PRODUCT](PRODUCT.md#41-生成记录与离页体验d-035) 为准。

```text
RECEIVED
   ↓ validate + idempotency
RESERVED  ← 原子创建任务、预留一次额度并记流水
   ↓
GENERATING ──文件保存且可交付──> SUCCEEDED (事务确认扣次后允许领取)
   └─云端确认失败/超时─────> FAILED (事务释放预留额度)

RESERVED 阶段执行交接失败或超时也须进入 FAILED 并释放预留。
```

请求号、云端参数指纹与重复请求处理遵循 [D-037](#44-请求号参数指纹与幂等d-037)；它们不能代替可信身份、额度与文件权限校验。

### 4.1 一次结算与迟到结果

- **成功条件**：PDF 已保存且云端确认可交付，完成方仍持有当前有效执行批次。事务检查任务仍处于可完成的未结束状态、批次及期限有效、对应预留尚未结算，再同时提交 `SUCCEEDED`、正式产物引用、消费确认和不可变流水。只有事务成功后才能向用户交付文件；用户是否下载、是否留在页面不影响已成功任务的扣次。
- **失败/超时条件**：由可信云端确认执行失败或期限届满；事务重新读取并校验当前任务状态、批次及超时依据，再同时提交 `FAILED`、释放对应预留并记流水。不能拿事务外读取的过期状态直接退款；重复回调、重复对账只能得到已有结算结果。
- **终态不反转**：`SUCCEEDED` 和 `FAILED` 不能相互转换。成功与失败竞争时，只能有一个符合条件的事务完成结算。已经失败的旧执行批次即使随后上传文件，也不允许交付或重新扣次；已经成功的任务也不能被迟到的超时检查退回额度。
- **产物清理**：候选文件按任务/执行批次隔离。迟到、重复或未完成提交的产物须对账清理，只删除未被成功任务引用的文件，不能误删已提交的有效结果。数据库事务无法同时包住云存储上传，必须覆盖“上传成功、状态提交失败”的故障窗口。
- **重新生成**：失败任务保持失败；用户主动重新提交时创建新任务并重新校验/预留额度。仅查询、客户端重试同一请求或重复下载都不产生新消费。文件到期只影响交付可用性，不改变生成终态。

事务只包住任务、额度和账本修改，**不要把 PDF 生成或云存储上传放进数据库事务**。执行批次、可信时钟/期限判断、事务冲突重试与流水去重方式需结合 CloudBase 能力实测，不引入独立服务器或通用工作流框架。

### 4.2 受理、离页与结果查询

云端返回“已受理”前必须持久记录任务与预留，并完成可验证的执行交接，使任务推进不依赖客户端保持请求或页面存活；不能在函数返回后用未等待的异步调用冒充可靠执行。具体 CloudBase 调用/调度方式仍属于 O-008 的实施验证，不因此默认持久化正文。

客户端等待超时、断网、离页、关闭小程序或更新重启均不自动改变任务状态或释放次数。客户端根据原幂等请求/任务编号查询归属当前用户的云端记录；尚未确认受理时不得当作成功提交，也不得因响应丢失自动创建第二个任务。进入历史列表/详情时重新获取结果，页面刷新策略见 PRODUCT。

函数异常、执行交接失败、长期未结束任务由可信超时恢复/定时对账按 4.1 节结算，并按下节限定恢复范围，避免永久预留额度。

输入校验包括受支持的排版版本组合、模式、参数范围、最大字数、页数、体积、每用户并发量和速率限制；导出前须按 [版本匹配规则](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032) 核对云端复算与预览布局一致，不兼容或不一致的请求不得继续导出或扣次。

### 4.3 不保存正文的恢复边界（D-036）

**已确认，实现与故障验证待完成。** 首版不自动重新排版，不为自动重试保存正文、含原文的布局快照或可重放的正文载荷。生成过程可处理用户提交的内容，任务元数据及私有 PDF 仍按既定规则保存；恢复机制只处理状态、已有产物和账本，不从 PDF 提取正文重做。

| 恢复时的可信云端状态 | 处理 |
|---|---|
| 原执行仍有效、尚未结束 | 继续等待原执行；客户端离页、断网或暂未发现文件都不足以判失败 |
| 任务已成功，只是响应未送达客户端 | 返回已有状态，在有效期内领取同一 PDF，不再次生成或扣次 |
| 完整 PDF 已保存，成功事务未提交 | 核验产物及任务/执行批次关联；仅在任务未结束、批次/期限仍有效且满足 4.1 节成功条件时，幂等补完成功结算 |
| 云端确认执行中断且无可用完整产物，或已经达到云端超时条件 | 按 4.1 节确认失败并释放预留，不另起渲染执行；不可用产物按规则清理 |
| 任务已失败后才发现产物 | 保持失败，不交付、不重新扣次，清理未被成功任务引用的文件 |

已有文件不意味着一定可以补成功：无法验证文件完整性或任务关联时不得交付，过期执行也不能绕过终态与期限校验。恢复器不能仅凭一次存储查询失败就释放额度；须取得可信失败依据，或由云端超时处理收敛。

需要重新生成时，由用户主动提交新任务并重新校验、预留次数；若编辑器内仍保留原输入可继续使用，否则需要重新粘贴。历史记录不恢复作文原文，不提供无输入的一键重做；成功 PDF 到期后也不自动重建。重复查询、客户端对同一请求的重试、事务冲突重试及已有文件结算重试仍须幂等，它们不属于重新渲染。

### 4.4 请求号、参数指纹与幂等（D-037）

**已确认，实现与并发验证待完成。** 按 D-050，前端为一次明确的生成操作生成随机唯一的 `requestId`，整号绑定云端签名的受理时间窗与客户端可靠安全随机部分；不用时间戳或 `Math.random` 充当随机源。第一次点击即固定完整请求号与本次参数快照，双击和网络重试沿用原号和原时间窗；不能在每次网络调用时续签或重新生成号码。用户修改内容后主动生成或明确再次生成时使用新号，即使内容相同也属于新任务。快照只用于本次提交，不因此默认持久化正文。

云端从可信微信上下文获取用户身份，以 `(userId, requestId)` 为幂等范围，另生成 `jobId` 标识任务。请求号使前端在尚未获得任务号时也能查询受理结果；任务号用于进度、历史结果和文件领取。可以保存必要的请求号/任务号以便重开后查询，但不连带保存正文；知道任一号码都不能绕过归属校验。

| 同一可信用户下的请求 | 云端行为 |
|---|---|
| 已有请求号，参数指纹一致 | 返回原任务及当前状态，不重复布局/渲染、预留或消费；失败任务仍失败，文件过期也不自动重建 |
| 已有请求号，参数指纹不同 | 明确拒绝（建议错误码 `IDEMPOTENCY_CONFLICT`），不交付旧文件、不覆盖原任务、不自动另建任务或扣次 |
| 有效的新请求号 | 正常校验并创建新任务，按既定规则成功后计一次 |
| 请求不存在且签名时间窗已过期，或原号被篡改 | 明确拒绝，不把清理后的重试当作新生成；用户只能主动发起新操作 |

**参数指纹**由云端从收到的实际参数计算，建议采用 HMAC-SHA-256，密钥仅在可信云端保存。绑定可信用户与请求号，并覆盖工具/导出类型、标题、正文、描红开关、允许的文字设置及完整排版版本组合（内核、模板 ID/预设版本、字体/度量资源版本）。所有影响结果的参数都要参与；用户身份、默认值及预设引用不能由客户端任意覆盖。字段顺序、默认值表达及文本编码采用确定性规则，保留有意义的空格、显式换行/空行，不裁剪或整理正文。

指纹随任务记录保存算法/规范化版本及密钥标识，重试按原校验版本比较，不能因部署或密钥轮换把同一请求误判成不同内容。云端自行计算，不接受客户端自报指纹作为一致证明。指纹用于相等性校验，不用于恢复正文或重做，也不作为公开查询键、日志字段或跨用户内容索引；它仍按受保护的任务数据管理。

参数指纹用于识别“同一请求有没有改变参数”，D-032 的**布局摘要**用于核对“预览与云端布局是否一致”，两者职责不同：前者按幂等所需期限保存，后者仍按架构规则在生成时核对，不因此要求长期保存布局或摘要。

**并发与清理**：云端在同一事务内重新确认 `(userId, requestId)` 是否已占用，并原子提交请求与任务的绑定、参数指纹、额度预留和流水；通过事务冲突检查/唯一性约束确保同号并发只受理一次，具体数据库实现待验证。身份和基础输入限制每次都校验；命中旧任务不因当前 active 预设变化、时间窗到期而重新生成。签名窗口必须在完整请求号内，不能用可续期的独立令牌让同一旧号重新有效。

请求/指纹保留期由服务端显式配置；清理至少等到签名窗口到期、任务终结及配置保护期满足，未终结任务不得丢失去重绑定。提前删除可见记录时保留最小去重墓碑到保护期结束，对重复请求返回不可恢复/已删除状态，不重建。指纹原密钥/规范化实现保留至相应受保护记录到期；旧密钥缺失应明确拒绝，不能按新密钥创建另一任务。PDF、记录、去重和账本分别管理，文件可领取期限不得长于其授权记录保留期；生产具体数值与删除告知仍属 O-007 最终配置验收。

## 5. 支付和广告（未启用）

支付需要云端订单、支付确认（平台服务端回调或可信查单）、幂等赠送权益、退款与补偿。广告奖励也需要可靠的奖励完成验证与重复领取防护。前端上报支付成功或视频看完不足以直接加次数。

个人主体虚拟支付及广告支持条件和限制须在实际申请时核对，不提前承诺一定可开通。

## 6. 统计口径

D-049 确定首版实现口径。时间按 `Asia/Shanghai` 自然日；页面显示所选日期、数据覆盖范围和服务端统计时间。管理员每次请求仍独立鉴权。

- **新增用户**：当日首次建立内部用户记录的去重用户数。
- **DAU**：当日发生至少一次可信新生成受理或有效 PDF 开始领取的去重用户数。按用户与日期幂等记录最小活跃事实；同请求重试、后续文件块、轮询、预览和管理员读取不产生额外事件。不把此指标称为所有页面访问人数。
- **成功生成**：当日首次进入 SUCCEEDED 的独立任务数（按完成时间，非导出格式数、下载次数）。
- **模板热度**：按当日成功任务关联的模板统计，预览不计。
- **失败率**：当日失败终态任务 / 当日全部终态任务；重复请求不重复计，未结束任务不进入分母，无终态时显示“暂无”，不伪造 0% 成功率。
- **收入**：已核实的支付金额与退款分开；不能以客户端成功页计收入。
- **额度消耗**：以 `credit_ledger` 的完成消费流水计量。

首版低量时由服务端分页查询最小安全记录并聚合，页面进入与主动刷新更新；重试不会新增用户、任务、消费或活跃事实。必须覆盖所有分页，达到资源限制时明确失败或标示不完整，不将截断扫描作为完整结果。生成终态、流水和幂等活跃事实可对账，不通过客户端埋点推断成功。保留期以外的数据明确不可用；未来若采用日汇总，须在原始记录清理前完成可重入汇总与对账。小程序管理员只读取汇总，不列出文章正文、私人标题或任意用户原始数据。

## 7. 隐私与清理

文章原文只在有明确必要的生成过程中处理；不默认永久保留云端文本。生成产物设置短期保留和过期清理策略；日志绝不写正文、原始文件、密码、支付密钥。隐私告知、账户数据删除机制、保留期限等在上线前必须定稿。

按 [D-037](#44-请求号参数指纹与幂等d-037) 保存必要的带密钥参数指纹，用于同一请求号的异参检测；不保存可重放的正文或布局快照，不将指纹当作匿名数据。其保留期限与过期请求处理随 O-007 定稿，不能无限期保留或清理后引起重复消费。
