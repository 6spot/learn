# 微信云开发与 CloudBase 接入

> 状态：业务与维护组合已实现并通过本地检查，尚未实际部署。真实账号、环境权限与运行能力按 [最终验收](FINAL_ACCEPTANCE.md) 配置和验证。

## 1. 技术选择

- 前端：微信原生小程序（TypeScript / WXML / WXSS）。
- 主要后端：**与该小程序关联的 CloudBase / 微信云开发环境**。
- 前端主要通过 `wx.cloud` 调用云函数，避免为初期业务自建 API 网关与 HTTP 域名。
- 初期不建设 Oracle VPS、EdgeOne、Cloudflare Workers、独立 Web 服务。
- CloudBase 控制台用于数据库、函数、资源用量、日志和较深入的运营查询。

CloudBase 与 EdgeOne 不冲突，但当前业务没有必要引入 EdgeOne。微信云函数与其他网络/CDN 层的具体延迟应实测，而非假定所有云函数流量都由 CDN 加速。

## 2. 初始化环境

1. 微信公众平台创建/关联个人主体小程序并核实所属类目与账号能力。
2. 从微信开发者工具创建或关联可供该小程序调用的云开发环境。
3. 明确一个开发环境、一个正式环境及各自的环境 ID；不允许测试数据混入正式环境。
4. 云端身份从可信调用上下文获得微信身份；映射内部用户 ID。
5. 为函数、数据库和云存储配置最小必要权限；敏感管理数据仅可云端访问。
6. 函数部署、环境 ID 和密钥配置不写死到公开仓库；禁止上传支付密钥和密钥文件。

`wx.cloud` 与独立 CloudBase SDK/自定义微信票据登录并非可以随意混搭的同一接入过程；当前先采用小程序关联云开发的一条主路径。

## 3. 运行职责

### 云函数

- 可信用户身份解析、管理员校验
- 生成任务校验、幂等与额度预留/确认/释放
- PDF 文件渲染与交付（首版只支持 PDF，Word 留作后续）
- 读取经过授权的用户记录及管理员聚合数据
- 定期任务：清理过期文件，按 [D-036 恢复边界](DATA_AND_CREDITS.md#43-不保存正文的恢复边界d-036) 核验未终结任务的已有产物并结算/释放预留；不自动重新渲染。运营统计按管理员进入页面/主动刷新进行受限聚合，不依赖定时生成日汇总。

任务受理后的执行交接、终态结算和迟到产物处理遵循 [D-034/D-035 任务规则](DATA_AND_CREDITS.md#4-可信任务状态机d-034)，不得依赖小程序当前页面存活；历史查询和文件领取逐次校验任务归属。可靠执行交接方式及事务并发行为须在正式 CloudBase 环境验证，不能把返回响应后未等待的异步代码视作后台任务机制。

上述按**职责**划分，不要求每一项都是单独函数。部署数量随包体积、资源限制、冷启动时间和成本实际优化。

### 数据库

保存最小账户资料、额度及审计流水、任务元数据、汇总统计、配置；用户作文正文默认不持久化。

**后台维护的纸张预设**：已实现不可变的已发布组合、每模板当前版本指针及退休/删除保护。管理员通过 `publishPreset` / `activatePreset` 等受控接口操作，校验资源与在途引用并写安全审计，不直接改数据库绕过这些规则，也不建立草稿 CMS。客户端读取已发布版本用于预览；生成云函数按 [共享排版代码与版本匹配规则](ARCHITECTURE.md#31-共享排版代码与版本匹配d-032) 校验内核、预设及字体/度量资源组合，并复算核对布局。不能通过客户端提供的几何参数覆盖可信预设，也不能发布未经版式边界校验的规格。

### 云存储

为支持离页后从生成记录领取结果，成功 PDF 以私有文件短期保存，任务记录关联产物与有效期；每次领取验证当前可信身份、任务归属和文件有效性，不绑定最初发起生成的页面或连接。候选产物仅在成功事务确认后可交付，未提交或迟到的产物按任务规则清理；不要默认公开文件 URL。文件过期清理不改变生成任务的成功终态，具体交付期限仍待确定。

## 4. 安全、隐私与可观测性

- 云端每次验证身份和所有敏感操作；前端的角色、价格、额度与订单状态均不可信。
- 生产环境的数据库权限默认最小化；特权写入只能通过云函数。
- 函数日志只记录安全的任务 ID、错误类别、耗时与资源指标，不记录正文或个人敏感信息。
- 根据腾讯云函数超时/内存限制配置最大生成页数、大小和并发策略；防止耗时任务无限运行。
- 统计、临时文件和生成记录明确保留期限，并提供删除所需的程序入口。
- 使用 CloudBase 控制台监控错误、冷启动、执行耗时、资源点及账单，并配置成本告警。

## 5. 外部业务能力

个人主体对应的支付、广告平台申请条件以**最终上线时小程序管理后台实际开放能力及官方协议**为准。不要把 CloudBase 自己的普通商户支付能力等同于适用于个人主体的虚拟支付。

支付通知/主动查单须由云端确认并去重，广告奖励同样需要可信校验；二者都不能直接相信用户端“成功”提示。

## 6. 最终配置与发布顺序

以下由 Owner 在功能开发完成后执行，未执行前不能将验证标志改为通过。配置字段与校验以 [业务函数说明](../cloudfunctions/learn-service/README.md)、[维护函数说明](../cloudfunctions/learn-maintenance/README.md) 及其 JSON 示例为准；这里维护操作顺序，不再复制字段表。

1. 恢复锁定字体与依赖，运行 `npm run setup`、`npm run test:all`。完成字体用途许可和 [实体打印表](PRINT_ACCEPTANCE.md)，确定可发布的字体/预设组合。开发候选不能只改标签便视为已验收。
2. 建立互相隔离的开发/生产环境；配置禁止客户端直接访问业务数据库与私有 PDF 的规则。先在开发环境核验 SDK 的文档不存在错误码、上传文件号前缀、事务并发、函数内存/超时及调用响应限制，再记录运行平台验证结果。
3. 将已许可的固定字体文件部署至稳定 HTTPS 地址。在版本库外准备业务配置与独立密钥映射，填入字体 URL、免费额度、所有保留期限、请求/任务预算、统计覆盖起点及扫描预算。通过部署环境的密钥设施注入，不在命令行参数、截图或日志中写出密钥。保持身份映射密钥稳定，保留仍在保护期内的旧签名/指纹密钥。
4. 运行 `npm run build:cloud`，部署 `dist/cloudfunctions/learn-service` 和 `dist/cloudfunctions/learn-maintenance`。业务函数全程等待执行与结算；维护函数依次等待恢复和生命周期清理。验证后者拒绝小程序客户端调用，再配置唯一可信定时入口及资源/费用/清理积压告警；未验证的权限标志保持 `false`。
5. 使用真实账号调用 `getAccount` 取得服务端内部用户号，在受控配置中设置管理员。以该管理员的可信微信上下文调用 `publishPreset`，附真实验收证据；此步骤会实际读取并核验前面部署的字体。接口见 [预设注册](../packages/cloud-service/README.md#t12-可信预设注册)；普通客户端自报用户号、角色或控制台模拟 event 均不能替代可信身份。
6. 填写 [公开配置](../config/public.example.json)，运行 `npm run build:release -- --config <配置文件路径>`。导入 `dist/release`，验证 AppID/环境/字体与业务函数一致；上传微信体验版本。确认目标客户端已可用、云端支持与客户端就绪记录正确后，再用 `activatePreset` 切换每模板当前组合。日常开发导入仓库根目录，两种产物分开；正式发布也按先云端和资源、后客户端、最后激活的顺序。
7. 按 [最终验收](FINAL_ACCEPTANCE.md) 用至少两个账号完成生成、离页、重复请求、PDF 领取、跨用户拒绝、删除及统计对账。核对隐私页的实际时长，验证真实更新保护输入，完成备案/类目/隐私声明后再正式发布。保存提交号、配置版本、字体散列、设备及日期，不保存用户正文或敏感凭据。

## 7. 更新与回退

- 发布前保留上一版函数产物、小程序版本及受控配置版本。先部署兼容的云端与资源，再发布客户端，最后切换每模板当前预设；旧任务所需实现、预设、字体与密钥必须继续可用。
- 只有已发布、仍受支持且资源完整的旧预设才能重新 `activatePreset`；客户端已锁定且仍受支持的组合按原组合继续。不能修改已有不可变预设，不能把尚未发布的开发候选当作回退版本。
- 函数回退前确认旧代码理解当前存储与账本结构，并保留同一身份密钥及所需请求密钥。回退不撤销成功消费、不复活失败任务、不删除未知执行结果；继续运行兼容的恢复/清理程序使已有任务收敛。若旧代码不兼容，保留当前状态并做向前修复。
- 小程序通过微信正式版本管理发布/回退，不下发可执行 JavaScript 热更新。更新提示、用户输入保护与重新预览遵循 [应用更新契约](ARCHITECTURE.md#32-不受支持版本的微信更新流程d-033)。
- 变更保留策略不能破坏已有任务、签名窗口和迟到 I/O 的保护边界；已创建记录按其期限处理，历史窗口上界必须覆盖旧部署。版本回退和数据恢复均不得用人工改余额代替事务结算。
